# Dynamite UV Storyboard：独立编辑器方案

**状态：2026-11-27 设计，未实现。** 当前先做[首轮脚本与画面规格](storyboard-script-spec.md)：用手写脚本在游戏里验证指令、格式和实际效果。本文的独立编辑器、内置代码页和 C#／C++ SDK 是下一阶段设计，等播放语义验证后再推进。osu! 的规则见 [Storyboard 完整功能参考](storyboard-research.md#2-完整功能速查从声明到动作)。

## 下一阶段的作者工作流

打开一张已保存的 UV 谱，直接拖动标题、灯和定位点。想让灯绕着一个点转、按拍复制十六次，或者读音频做频谱，就在编辑器的代码页写生成器，点“生成”看效果。调颜色、持续时间和中心位置不必回代码：这些参数可以让代码声明出来，由检查器显示，位置参数还能在画布上拖。DynaMaker UV 仍负责制谱；两个工具各自保存。

建议明确分成两步：**生成效果时运行作者代码；游戏播放时只读已经生成的演出数据。** 作者用的是完整语言和 SDK；玩家不装编译器，也不运行别人附带的 `.cs`、`.cpp`、DLL 或 WASM。输出可以有和 `.osb` 一样一眼能读懂的“对象＋动作”文本，但不需要沿用它的缩进、数字缓动、4:3 坐标或历史行为。

首个试用任务仍是一段副歌：手摆标题，用一小段代码让灯带按拍交替，回到画布拖灯带中心，再单改第四次的亮度。然后故意写错一行，能点错误跳回代码，修复后继续看演出。能做完这段，比有没有一排粒子、频谱和镜头特效面板更重要。

| 想做的事 | 建议做法 |
| --- | --- |
| 按歌曲做完整演出 | 全曲时间轴、拍网格与真正的音频波形；属性关键帧、曲线、片段和跨段复用。 |
| 把几次动作变成几十次 | 在内置代码页写生成逻辑；检查器调次数、颜色、错峰和位置，画布上能看见输出。稳定 ID 支持只改其中一次。 |
| 让画面适配三面轨道 | 布局模板、判定线/HUD 辅助线、三面选择器、真实音符合成预览。首轮可玩演出全部在判定线和音符后面。 |
| 内容交给别人后仍是一致的 | 草稿、谱包中的发布版本、游戏播放、现有视频导出各有明确入口；预览和游戏用同一套求值规则。 |

## 1. 编辑器怎么用

### 工作台布局

```text
┌ 项目 / 当前差分 / 未保存状态     播放 · 循环 · 逐帧 · 拍／秒 · 预览模式 ┐
│ 文件 / 素材 / 场景树       舞台〔场景 | 代码 | 并排〕     属性 / 公开参数 │
│ 手工对象 / 生成器 / 输出   1920×1080，三轨与 HUD 对照    编译状态 / 来源 │
├ 时间轴：波形、段落、BPM、对象片段与关键帧                            ┤
└ 问题与输出：点错误跳代码，点警告定位对象和播放时间                   ┘
```

- **进入项目。** 新建演出时选择已保存的目录谱包和差分，显示实际所用录音，以及这个差分的 BPM 与音频偏移。也可开一个自由练习项目，先只加载音乐。DynaMaker 有未保存改动时，Storyboard 编辑器明确提示自己读的是磁盘版本，不偷偷接管制谱器里的草稿。
- **画布。** 拖图片进来即可移动、缩放、旋转、设置旋转中心。支持多选、对齐、等距分布、吸附到参考线；对象即使移出画面也能在图层树找回。画布缩放和平移不改变作者坐标。暗底和棋盘背景只影响编辑视图。
- **图层树。** 分组、排序、搜索、锁定、隐藏与独显。锁定和独显只作用于编辑器；发布显隐是独立选项，防止作者为了查看某张图临时独显，导出时把其他图都删了。
- **时间轴。** 首先做波形、播放头、拍／秒刻度、片段起止、基础关键帧和 A/B 播放范围。支持拍网格与段落标记吸附、复制和移动。不要给每种过程效果建专用时间轴：生成器默认显示为一个可展开的片段，跳到结果或改参数就够用。
- **检查器。** 普通对象直接改位置、颜色、显隐等基础属性，也能给位置和透明度打关键帧；程序对象显示脚本暴露的强类型参数。拖动正在动画的普通对象时，明确是修改当前关键帧还是整条轨偏移，松手可一步撤销。高级曲线与路径先由 SDK 表达，有使用需求再补对应编辑工具。
- **代码页。** 文件标签、语法高亮、补全、跳到定义、诊断与日志，支持一键生成、停止、定位报错。源文件仍保留为普通文本，作者可用 Git 或外部编辑器，但核心工作流不要求另开 IDE。第一步只在手动点击时运行，之后允许已信任项目选择保存后重生成。开项目时不执行代码、构建脚本或恢复依赖。
- **预览。** 演出单独看、谱面单独看、合在一起看。合成模式可以开 Note 轨迹、安全区、Mirror、不同落速和动效等级，也能固定一个时间点并排比较 Full/Reduced/Off。可播放、暂停、拖时间、逐帧和循环一段。这里的循环用于练习；作品正式重复要在时间轴上加“重复”动作。
- **素材与草稿。** 导入只读复制到草稿素材库；工程移动后不依赖 `C:`、盘符或网盘挂载。素材显示引用数、缩略图、尺寸、来源和替换影响。缺素材时可以重链接或用占位继续编辑；发布前报错并定位。自动恢复单独写入，不覆盖上次手工保存。以草稿重新打开时保留可编辑生成器和模板关联；窗口布局、当前选择和播放位置留在用户设置。

### 从空白做一段副歌

以下是一段待制作的原创练习曲：四拍一小节、120 BPM。如果小节 0 对应音频 0 秒，第 8 小节就是 16 秒，第 12 小节是 24 秒。换一首歌时，编辑器按当前差分的 BPM 和对轨设置计算。

| 音乐位置 | 作者在界面里做什么 | 验收时看什么 |
| --- | --- | --- |
| 第 8 小节 | 拖入一张自制标题图，画布上放好落点，在时间轴打两个位置关键帧。 | 不写代码也能完成一次入场；跳到中段与正常播放时的同一帧一致。 |
| 第 8 小节起，到第 12 小节前 | 从模板新建 `BeatLights`；在内置代码页循环读取 16 个计划拍点，交替生成左右灯。生成后在画布拖动发光中心，检查器降低第四个输出的透明度。 | 不开 IDE；重生成不丢手动中心和第四次例外；16 次交替顺序仍正确。 |
| 编排过程中 | 故意让一次生成出错，点诊断跳回源码，修完重新生成。然后复制这个生成器实例到再现段，改该实例的颜色。 | 失败不换画面，旧结果明确标记为旧；同一段代码可有两套参数，不需要复制源文件。 |
| 进阶练习 | 用 SDK 生成外场粒子，把一张自制歌词图按媒体秒放到人声处。 | 拖播放头不换粒子；歌词不随 BPM 编辑漂移。粒子和字幕专用面板不作为原型门槛。 |
| 正式发行链路完成后 | 在游戏内以相同差分预览；用现有录制入口取一段相同的画面。 | 比对同一媒体时刻、构图、素材和音符；关演出前后，谱面与成绩身份不变。 |

## 2. 场景和代码各管什么

| 浏览场景时看到的对象 | 真正写入哪里 | 再生成会怎样 |
| --- | --- | --- |
| 普通对象：标题、图片、手工组 | 工程场景和对象关键帧。 | 不受脚本重生成影响。 |
| 公开参数：中心、颜色、次数、素材、时间窗口 | 生成器实例。代码声明稳定参数 ID、类型、单位、默认值和范围。位置参数可绑定场景锚点，或直接用拖拽手柄。 | 传给下一次生成。两个实例可共用一份代码、各用不同参数。 |
| 生成对象：某次亮灯、某个粒子 | 默认只读，能找到生成器来源；有稳定输出 ID 时，可对允许属性写显式覆写，例如叠加位置偏移或替换透明度。 | 同 ID 重新应用覆写；如果 ID 消失或类型变化，显示孤立覆写，不能自动套到排序最近的对象。 |
| 分离后的对象 | 成为普通对象；原生成器对该输出 ID 有排除项。 | 无重复显示；撤销分离时同时恢复原输出。没有稳定 ID 的输出只允许显式制作快照，不能假装会跟后续生成同步。 |

拖动前，检查器告诉作者改的是哪一层：**源参数、生成结果覆写，还是普通对象**。不自动从画布反写 C#/C++ 源码。第一版建议只提供位置、旋转、缩放、基础属性与关键帧、选择/排序/分组、预览和参数检查器。高级复制和排布、参数联动、路径、频谱、粒子行为优先由程序 SDK 解决，常用且确有需求的再做控件。不要把另一套节点编程和完整 IDE 都塞进首版。

生成任务按修改版本排队，只更新受影响的实例；源文件、参数、依赖快照更新时，旧任务即使先返回也不能提交。失败时保留上一份成功结果以便继续浏览，片段标“预览过期”，不能默认用旧结果发布。生成结果逐项显示对象数、素材和时间范围。作者可直接查看少量命令，以及生成来源文件、行号或带名字的逻辑标记。

### 一个 SDK，两种入口

| SDK 能力 | 给作者什么 | 不交出的权限 |
| --- | --- | --- |
| `Context` | 当前差分、BPM、精确拍位、计划 Note、段落标记、显式参数、固定种子；后续按需加宿主预算内的频带数据。 | 不给游戏会话、任意本机目录、账号或玩家实时输入。 |
| `SceneBuilder` | 创建对象和组；设置素材、层、变换、颜色与显隐；提交带范围的动作、有限重复和稳定 ID。 | 不返回 Godot 节点、文件句柄或原始指针给发布数据。 |
| 诊断与预算 | 记录语法错误、作者日志、输出对象/素材/命令数与验证位置；超限可取消，不改工程。 | 不允许生成器把结果直接写进真实谱包。 |

程序可以运行循环、数学和自定义算法，但编译器**不会把任意 C#/C++ 翻译成游戏脚本**。程序是在作者阶段实际运行，SDK 把它创建的对象、通道和动作记录下来，再输出受限的演出。举例：代码计算频谱后提交 `ScaleY` 轨，播放端只读这个轨，不运行 FFT；代码用随机数生成粒子轨迹，播放器不按帧执行作者的粒子逻辑。若将来要根据实战命中触发，只能在输出里声明有哪些受支持事件和动作，不能随谱发布回调。

下面是**拟议 API 示意**，不是已有库；`BeatRange`、`Anchor` 和时间单位到实现时再冻结：

```csharp
void Build(Context ctx, SceneBuilder scene)
{
    var centre = ctx.ParamPoint("centre", x: 960, y: 540); // 画布能拖
    foreach (var beat in ctx.Beats(ctx.ClipRange))
    {
        var id = $"lamp:{beat.CanonicalKey}"; // 不是返回列表的顺序号
        var delta = beat.Index % 2 == 0 ? -320 : 320;
        scene.Sprite(id, ctx.Asset("lamp"), centre.Offset(delta, 0))
             .Lifetime(beat.Time, beat.Time.PlusBeats(1))
             .Fade(beat.Time, beat.Time.PlusBeats(1), 0.6, 0.0, Ease.SineOut);
    }
}
```

C++ 入口沿用同样的参数 ID、时间与输出约定。下面用同一段效果示意，不是已经发布的头文件：

```cpp
void build(const uv::Context& ctx, uv::SceneBuilder& scene) {
    const auto centre = ctx.param_point("centre", 960, 540);
    for (const auto& beat : ctx.beats(ctx.clip_range())) {
        const auto id = uv::key("lamp", beat.canonical_key());
        const auto delta = beat.index() % 2 == 0 ? -320 : 320;
        const auto begin = beat.time();
        const auto end = begin.plus_beats(1);
        scene.sprite(id, ctx.asset("lamp"), centre.offset(delta, 0))
             .lifetime(begin, end)
             .fade(begin, end, 0.6, 0.0, uv::Ease::SineOut);
    }
}
```

`ctx.beats` 在这个例子返回片段 `[开始, 结束)` 内的整拍；样例恰好在拍边界结束。真实工程里，切短片段应在该处裁切预览，而不是偷偷将拍间渐变拉短。两种语言都应保留相同的规范化 ID，避免只改语言就丢手工覆写。

C++ SDK 可用小型头文件包装有版本的构建接口；若评估原生路径，让编译结果作为一次性进程，通过有限大小的消息返回结果。不要把 C++ 对象 ABI 或指针作为跨进程合同。相同输入、种子和受约束数值的夹具应产出一致的规范化结果，任意数学库不承诺跨语言位级相同。

### C#、C++ 与编辑器选型

| 部分 | 建议 | 原因与代价 |
| --- | --- | --- |
| 编辑器主体 | **Avalonia/.NET 10 + Godot 预览先做原型**；编辑器和代码运行进程彼此独立。 | 复用仓库已有 C#、桌面和 Godot 展示经验。画布可先独立窗口验证，再验证嵌入、焦点与 DPI；不继承制谱器 Shell 的所有交互。 |
| C# 生成器 | **第一条实现链**。用 [Roslyn `CSharpCompilation`](https://learn.microsoft.com/en-us/dotnet/api/microsoft.codeanalysis.csharp.csharpcompilation) 编译指定源与固定引用；代码页用 Roslyn 工作区做诊断/补全，不通过执行项目的自带构建步骤来获取语法信息。产生的程序集只进作者侧 worker。 | 标准库与现有 C# 核心较易接，编辑体验先成形。编译和运行仍分开审核；Roslyn 不是安全容器。 |
| C++ 生成器 | **第二条实现链，不取消。** 优先做固定工具链的 `clang++ → WebAssembly → 作者侧 worker` 试验，使用 [wasi-sdk](https://github.com/WebAssembly/wasi-sdk) 或固定 WASM target 作为候选；优先只开放 SDK 需要的宿主导入，不默认给目录、时钟、网络和进程能力。代码页接 [clangd](https://clangd.llvm.org/design/compile-commands)，由编辑器提供固定目标、sysroot 和头文件配置。 | 工具链、运行模块限制、标准库支持、安装体积需要验证。WASM 只用于作者生成，不进入游戏。若试验欠成熟，信任的本地工程可另评估原生 `clang++`/MSVC 子进程；不能因原生编译快就把生成 DLL 载进主编辑器。 |
| 统一播放器 | C# 实现纯数据规范化和按时间求值，Godot 负责画面；先用 CPU/内存和渲染数据找瓶颈。 | “作者写 C++”不意味着游戏得用 C++ 或 FFI。如果以后确有某个运行热点，换实现而不换作品格式。 |

**运行边界。** 下载的工程与模板默认只读、禁用运行；打开、预览已有产物或恢复窗口时不执行代码。初期仅运行作者明确选择的本地可信工程，不装任意 NuGet/CMake 插件，不调用项目提供的编译器、分析器、生成器或构建钩子。Worker 使用只读输入快照、独立输出和资源上限；生成失败、超时或取消时清理整个任务进程树，主编辑器不受影响。

安全能力得单测：微软说明 [`AssemblyLoadContext`](https://learn.microsoft.com/en-us/dotnet/api/system.runtime.loader.assemblyloadcontext) 只隔离程序集加载，不限制权限；[Windows Job Object](https://learn.microsoft.com/en-us/windows/win32/procthread/job-objects) 管进程树和资源，不替代文件/网络权限。若要接受外部 C# 工程执行，须先验证最小权限的 [AppContainer](https://learn.microsoft.com/en-us/windows/win32/secauthz/appcontainer-isolation) 或等效方案。C++ 的 [Wasmtime 隔离说明](https://docs.wasmtime.dev/security.html)说明了 WASM 的隔离模型，宿主导入、时间限制、最大内存和输出校验仍由编辑器落实；未验证前不要宣传“安全运行第三方代码”。

首版谱包不携带执行文件、代码、任意 shader、外链资源、Godot 场景或 3D 场景包。它可以由复杂程序生成，但落盘只能是允许的对象和动作；不能调判定、计分、伤血、落速或监听原始输入。

## 3. 时间、坐标和游戏画面的规则

### 音乐是作品的时间轴

建议让每个**片段**选一种时间基准：**按拍**适合灯带、副歌卡点；**按秒**适合对白、歌词和逐帧对口型。首轮脚本用两种基准在同一场演出里做对照：每个顶层对象树只选一种，组内继承；作者工具可在同一时间轴并排摆这两类对象，切换显示刻度。插值、裁切、重复与变速都发生在该片段选定的单位内：同一个按拍渐变跨过 BPM 切点后，剩余的拍会变快或变慢；按秒渐变不受影响。比如灯带应当在四拍内渐暗，就选按拍；同一行歌词必须在录音 `00:12.350` 出现，就选按秒。若前三拍为 120 BPM，最后一拍为 180 BPM，灯带总长约 1.83 秒，歌词仍在原来的录音位置。

- 按拍保留 UV 的精确 `BarTime`；编排和吸附不经显示秒数往返。按秒的发布候选是整数媒体毫秒，界面可显示 `00:12.350`。转换由用户发起，先预览边界移动、舍入和冲突，再一次提交。
- 用当前差分的 BPM 和**谱面**音频偏移建立拍↔媒体时间映射；改对轨、换录音或切差分时显示影响列表并要求确认。默认生成的“按 Note 打点”使用谱面计划位置，不使用实时判定；必须明确重建，列出新增、丢失和改位的锚点。不隐式绑定到默认差分的 BPM。
- 游戏、录屏和编辑器拖动都按“当前媒体时间 → 画面状态”求值。正放到 30 秒和直接跳到 30 秒应取得相同对象、属性、帧号及粒子种子状态。游戏同一帧提供去除**玩家**判定校准的媒体采样，不另外读播放器，不改判定流程。暂停冻结，恢复不补跳粒子。实际编辑器预览与游戏可以用不同运输钟，但必须对同一媒体时刻取同一状态。
- 对象和片段采用 `[开始, 结束)`；跨段接力以新片段的起始状态为准。同属性同刻时，“替换既有帧”须显示被覆盖的值，文件不接受不明顺序的重复帧。首个关键帧前用基础值，末帧后保持末值直至片段结束；需要突然变化用阶跃。颜色存储/插值空间、混合和透明度应在原型期以截图样张冻结；建议线性光插值、有限数值、透明度限制在 0–1，sRGB 供面板输入。旋转存明确角度和圈数，不擅自走最短弧。
- 首轮游戏播放限制在实际录音区间内；负起始片段可在草稿标警告，但可玩包的显示不得早于媒体 0 或晚于音频结束。未另行定义片头、跳过或片尾延时之前，不延长结算等待，也不改变 BLEED 当帧失败。视频逐帧用已有固定 60fps 时间线，不写另一套“看起来一样”的合成器。

### 三面舞台怎么分层

坐标取游戏 1920×1080 内容区，左上为零，保持等比黑边。图像可放在画布外做入场，但输出裁在内容区内。共享舞台有自身的局部 Y 偏移，编辑器必须从正式游戏画布统一映射，不直接拿 stage-local 坐标当文件坐标。判定线和 HUD 辅助线从共享几何产生，禁止另存一份会漂移的数值。

```text
最前    游戏 HUD、暂停与结算
        游戏音符、判定线与必需提示
        Storyboard 内部前后排序（统一仍在判定线背后）
最后    游戏原背景「离子余辉」
```

首轮不开放覆盖判定线或音符的 Overlay。作者可预览遮挡、过高亮度和红色闪变风险，也能按颜色、透明度和覆盖面积过滤问题。镜像默认只改变游戏轨道，演出不自动翻转（歌词不倒过来）；未来如需灯带随玩法镜像，仅显式标记的轨道绑定对象跟随。设置建议给 Storyboard 自己的 Full / Reduced / Off：Reduced 使用经审核的低动替代、弱化或禁用密集粒子/强加色/大幅镜头动作；没有可验证替代时显示安全静态背景或停用风险层。Off 跳过加载新演出资源、保留游戏原背景，与命中特效档独立。

## 4. 工程文件、谱包和现有程序怎么接

### 各自管什么

| 归属（拟议） | 拥有的职责 | 不该接手的事 |
| --- | --- | --- |
| 新建 `storyboard-editor/` | 独立 Windows 编辑器、场景／时间轴、内置代码页、作者 SDK 与单独的编译／生成进程、项目保存和恢复。 | 不引用制谱 Shell，不共享其可写文档和撤销历史；不把整个游戏嵌进去当画布。 |
| 无 Godot 的求值与合同 | 时间映射、数据校验、资源引用枚举、曲线和可见状态求值。建议放入已有 `shared` 的专门功能族；如果引用边界变大再另立纯 .NET 项目。 | 不读应用设置、不调用文件选择器、不碰判定和计分。作者侧生成器工作流不进入游戏程序集。 |
| `presentation` | Godot 贴图、形状、序列帧、遮罩、排序、资源生命周期钩子；同一套渲染适配供编辑器、游戏和录屏使用。 | 不持有两端会话；不从 `user://` 私自检索作者草稿。 |
| 游戏客户端 | 开局解析当前差分是否有演出、管理模式与加载生命周期、喂正式媒体时间；演出失败时按政策退回原背景。 | 不编译原始模板、不运行导入器、不替创作者补素材、不依赖编辑器。 |
| 谱包、商店和录制工具 | 谱包读写验证素材引用，商店只接受经过验证的发布数据，现有录制快照带齐该差分及可达演出素材。 | 不把草稿和缓存放进包，不随意扫整个目录后放行。 |

独立工程第一轮可比较两个预览形态：嵌入 Godot 子窗口，或让同一个预览进程单独开窗。前者方便画布直接操作，但已知 HWND、焦点、DPI、停靠与 Linux/macOS 扩展成本；后者先打通真实帧和 IPC，随后再评估嵌入。不要一开始模仿旧 Penpot 板，也不要用 UI 模型临时兼任游戏播放器。时间轴虚拟化、截取波形和曲线视图可以先在 Shell 原型测出来，不用等商店接入。

### 两种文件：可编辑工程与可玩的发布数据

作者工程放在谱包外，保存手工对象、源码、生成器实例参数、素材来源和手工覆写；自动恢复与窗口偏好另存。可另保留上次成功生成物供不开代码直接预览，但缓存不是工程权威。导出的是版本化**伴随文件（sidecar）**和所用素材，既没有生成器或编译器，也没有源码、撤销历史、绝对路径和调试缓存。频谱、文字等如由桌面计算，发布时烘焙为可核对的曲线或字形，不依赖玩家机器装的字体或分析插件。

[脚本规格](storyboard-script-spec.md#3-文本长什么样)给出已选用的 KDL 2.0 子集和手写示例。播放端读一次并整理成内存结构，再按时间取活动对象和属性值。若样片证明冷加载或体积成了问题，再评估同一模型的二进制缓存；先用原脚本的样片和参考数值对照，不能为缓存另定一套效果。

作者 SDK 以后应输出同一套数据并规范化格式。任意 IO 或非确定性算法无法保证可重现，构建记录至少要保存源码、SDK 和工具链版本、输入快照、种子和产物签名。

下面是记录关系的草图，供实现者对齐职责，不是要作者手写的 JSON：

```text
作者工程
  谱包引用 → 差分 ID、对轨和录音签名
  素材库   → 稳定素材 ID、相对路径、来源、导入设置
  源码     → C#／C++ 文件、SDK 和工具链版本
  实例     → 生成器 ID、参数、锚点、种子、输入快照及构建签名
  时间轴   → 手工对象、片段 ID、拍／秒、起止、生成输出覆写与分离例外

发布演出
  版本 + 一张绑定表：精确差分 ID → 演出
  每份演出：层顺序、有效区间、曲线／动作、相对资源 ID
  素材表  → 文件与受限解码信息
```

做阶段 A 原型时即可用这层关系思考对象 ID、撤销和重复；等阶段 B 的实际项目能重开，再冻结阶段 C 的发布表示。作者工程和发布演出分别迁移版本。播放器看到未知版本时不半解析；较旧作者编辑器打开较新草稿时也不覆盖原件。

| 决策 | 建议 |
| --- | --- |
| 如何绑定差分 | 初稿考虑专用保留目录及版本化索引（例如 `storyboard/index.json`），以精确 `chartId` 记录绑定；多个差分可显式选同一演出，但跨差分应用时要预览节拍和录音是否一致。路径和字段待冻结。不要拿旧草案的 `charts/<chartId>.storyboard.json` 直接使用：现行 ID 允许只差大小写，文件树不允许这种碰撞，旧包也可能已经占用候选路径。 |
| 能不能往现有 JSON 塞字段 | 不行。现行 v2/v2.1 解码器对未知字段报错；演出独立版本。只改演出不得改变 Gameplay Digest、规则版本和 BEST；缓存要用演出内容自己的哈希。以后上架时包修订、资源缓存和全包 SHA 仍可变化，它们不是成绩身份。 |
| 如何避免两边互相覆盖 | 原型只读谱包；首次可玩版默认**导出新目录副本**，重开并比较 gameplay identity 后才交付。发布前比较引用源的内容签名；原曲或对轨已变化时提示重绑。将来若允许两个编辑器原地保存，须先加共享写入事务/锁和并发检测；识别并处理差分重命名、复制、删除及引用计数。现有包 revision 并不是写入锁。 |
| 旧版可不可以玩 | 本地的新版客户端可做“坏演出停用、合法谱面仍可玩”并报明原因；包含演出的包在发布门禁或显式要求录制时应失败退出，不能悄悄录成无背景。非法路径与引用越界一律不能读。旧客户端可能本地忽略额外文件，但商店媒体 profile 有自己的安装门槛；旧版安装策略必须与服务端联动验证。 |

保存端的风险具体在 [V2 writer 的阶段目录及发布](../shared/Chart/V2/V2PackageWriter.cs#L76-L99)：当前会先复制原包整树，所以已有的未知文件并非必然被删。但同目录发布按 staging 目标集清理，在另一个进程改包时可能丢新文件或用旧副本覆盖；它也不知道还能不能删旧 chart 和媒体。商店的[精确引用检查](../server/Catalog/PackageInspector.cs#L23-L58)会拒绝额外数据；录制的[差分快照](../tools/chart-editor-core/Documents/EditorExportSnapshot.cs#L10-L43)只带现有音频与封面。这三条必须分别接入，同一份引用枚举贯穿保存、验包和录制。[现有正式录制](../client/scripts/video/VideoCaptureRuntime.cs#L52-L109)已经走游戏场景；不需要给 FFmpeg 再写一套视觉逻辑。[现有播放器时钟](../client/scripts/audio/SongClock.cs#L148-L176)与[判定调用处](../client/scripts/game/GameplayMain.cs#L250-L305)是正式采样的改造约束。

### 资源、读谱与移动端门禁

- **导入和发布拒绝**：目录逃逸、绝对路径/URL、大小写碰撞、reparse point、越权引用、不支持版本、循环依赖、非有限数值、解码尺寸超限、重复无序时间、未知素材和严重超预算。采用共享严格包路径语义；`res://` 要走 Godot 虚拟文件系统。
- **编辑器可报告**：预计活动对象峰值、纹理解码后字节、全屏透明层、加色叠加覆盖面积、每帧对象量、素材来源和未引用资产。上限同时约束作者工程的生成次数和发布数据解码/求值；现有 ZIP 大小限制不是移动端性能指标。纹理/图集按可达资源缓存；按时间区间找活动对象，属性轨二分取帧；保持绘制顺序，在允许的连续区域合批，不为每个对象开 Viewport。
- **可读性与闪变**：检测实际合成画面的亮度、面积、红色变化和短周期重复，定位时间和来源，生成标出三条判定线、音符与 Mixer 通道的复核视图。参考 [W3C 闪变说明](https://www.w3.org/WAI/WCAG22/Understanding/three-flashes-or-below-threshold.html)做候选警示，不能用单个频率阈值宣称游戏通过可访问性认证。对明确触发高风险规则的内容阻挡发布，而不是仅贴免责提示；涉及无法可靠判断的内容保留人工检查与低动模式。任何模式都不接受遮罩游戏 HUD、吞触控或修改音符材质。
- **性能数值怎么定**：先用三组自制场景测预算：普通副歌、密集外场、故意超过预算；分别比对演出 Off/Reduced/Full 的帧耗时、长尾卡顿、GPU 纹理内存、切歌加载和音频连续性。Windows 和实测 Android 分开记录。可先用 1080p60 检查桌面/固定帧导出一致性，不把它当 Android 性能承诺。在代表性移动设备上测到预算并冻结前，不以自动构建替代正式公开发行验证。
- **来源**：用原创或取得授权的媒体与字体。调研时看公开规范和工具实现，不把参考谱、曲绘、音效、skin 或示例素材带进产品。未来导入 osu! 时也不自动取得分发权。

### 后续功能先解决哪些问题

| 想加的能力 | 先做什么 | 什么情况才开下一步 |
| --- | --- | --- |
| 频谱／节奏跟随 | 桌面分析实际录音，把低频、中频或指定频带强度保存为可编辑曲线。波形负责找位置，频谱负责驱动画面；作者可试听、重建、调灵敏度。 | 如果作者连用几个真实项目仍需要录音之外的实时输入，再另谈实时分析。首轮无需引入。 |
| 前景演出 | 先只在安全区之外试一种受控叠层，提供固定裁切、低亮度、无输入和 Reduced 替代。 | 有样片证明放在判定线后确实达不到需求，且高密谱、Mirror、Mixer 和 Android 都能读清。 |
| 按实战事件变化 | 先用静态计划锚点完成按拍灯带。若要“实际命中才加一点光”，给编辑器准备可注入的假事件、限定时间窗、冷却、同刻顺序和重触发方式。播放器只消费归档后的事件；没有录过的事件不从 seek 位置猜。 | 先定重播、失败、Auto 和录制如何处理事件历史，再开放给创作。分支既不能影响玩法，也不能成为读谱必须信息。 |
| 片头、间奏与片尾 | 可先做同一歌曲时间内的段落模板和音量不变的视觉转场。 | 如果要超出音频时长或跨结算，专门决定跳过、暂停、尾部和结果时序，不能由附件中的最长动画控制游戏结束。 |

## 5. 开发顺序与验收门槛

| 阶段 | 提交什么 | 进入下一阶段之前 |
| --- | --- | --- |
| A · 脚本与游戏画面 | 手写原创样片；验证基础指令、文本写法、实际游戏分层、时钟与颜色。暂不做独立编辑器和 SDK。 | 见[脚本与画面规格](storyboard-script-spec.md)。在 Windows 本地以受控附件对照正常播放、跳转与高密谱读谱，不写真实谱包或商店。 |
| B · 独立编辑器及 C# 试用 | 复用 A 验过的效果模型；先做场景与时间轴，接 C# 编写/生成、参数与覆写、保存重开。 | 新作者不用外部 IDE 或终端完成副歌，能移锚点、单改第四次、重生成并重开。若 C++ 未完成则标明“C# 先行试用”。 |
| B2 · C++ 支持门槛 | 相同工作台提供 C++ 模板、编译诊断、工具链/目标版本和编译结果校验；验证 WASM 作者侧方案，原生方案只评估信任本地工程。 | 干净 Windows 环境可按说明使用，C++ 与 C# 为同一样例产出可互换的演出；生成超限、取消、坏输出时不影响编辑器、工程和预览。 |
| C · Windows 本地可玩 | 冻结第一版伴随文件合同；导出谱包副本；游戏读数据，合成预览对照 Full/Reduced/Off；现有视频快照接入。 | 游戏和视频能见同一演出，旧包仍可玩；无效演出按策略降级，关演出不改判定和 Digest。Windows 真实窗口/固定帧记录齐全；明确暂不支持商店。 |
| D · Android 与商店 | 上架审计、媒体 profile/旧客户端策略、移动设备实测、资源与闪烁门禁、发布文档。 | 旧版兼容、Android 触控与帧预算、切曲/重开、下载校验和未知版本分别通过；Windows 通过不能代替 Android。 |
| 后续 | 曲目片头/片尾、受控事件、进阶遮罩/音频分析、有限 osu! 导入。 | 每项先用样片证明现有做法不够用，再定资源、安全与回放合同；不将此行当发布时间承诺。 |

先把手写样片放进游戏看效果。进入阶段 B 后，再走完独立编辑器里的短链：手摆标题，内置代码页生成 `BeatLights`，拖锚点后重新生成，保存并重开。SDK 写出既有脚本数据；不能为了 SDK 的便利改变玩家看到的效果。A 不改商店、正式谱包或现有制谱器的保存行为。

### 要测到什么程度

| 验收项 | 例子与判定方法 |
| --- | --- |
| 场景与代码协作 | 手摆标题，再在内置代码页做 16 次灯带。分别测试参数拖动、第四次覆写、重生成保留覆写、删除 ID 后给出孤立提示、分离／还原、保存重开。测试有语法错、计算超时、旧任务迟到，不吞掉上一份有效结果。 |
| 双语言 | C# 与 C++ 的对照夹具使用同一谱面输入、素材 ID 和规范化单位，输出同一组对象和轨，验证同一媒体时刻的状态一致。作品导出内不含编译器、源码、DLL 或 WASM。 |
| 音画时间 | 同一关键帧分别用正常播放、正向跳转、倒跳、暂停恢复与固定 60fps 离线帧定位；比较确定性状态。跨速度切点分别测两类片段；改变玩家校准不移动演出，改变谱面偏移只按合同影响拍片段。 |
| 包和数据完整性 | 构造 `A`/`a` 差分、路径占用、缺素材、坏版本、超大图、过深循环；报错能定位且不读出包。正常谱包另存、复制或删差分、重新出片，检查可达媒体。模拟两进程先后保存，不能静默丢文件。只改演出前后比较 Gameplay Digest 及 BEST 归属。 |
| 游戏与录制 | 合成预览、Windows 客户端与视频采样同一批媒体点；比较位置、透明度、排序、帧号和降级行为。允许由 GPU/色彩管线造成的受控像素差异，不以跨 GPU 位级相同为标准；确认既有暂停、结算和 BLEED 时序不变。 |
| 读谱和设备 | 用高密谱、Mixer 转向、Mirror 和不同落速实打，确认画面不会遮挡必要信息；覆盖典型 Android 设备与不同 Windows DPI。性能和视觉验收分开记，在设备不足时不写通过。 |

## 6. 需要你决定的事

下面的建议可作为原型默认；还不是冻结合同。

| 选项 | 建议默认 | 理由 |
| --- | --- | --- |
| 第一个可玩的演出需要前景覆盖吗？ | 不开放，先全部在判定线后。 | 仍可做大部分编排，先测真实读谱，再决定是否需要带遮罩的前景。 |
| 启动方式 | 独立 Windows 应用；DynaMaker 入口后加。 | 现场验证可以直接开工程，制谱器现有保存不用随首个原型一起改。 |
