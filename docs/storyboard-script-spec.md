# Dynamite UV Storyboard：首轮脚本与画面规格

状态：2026-11-27，已选 **KDL 2.0 子集**，A1–A3 已接入 Editor/Internal 的本地游玩原型，语义仍可在开发期调整。使用方式、实际效果与测量见[舞台原型与验证](storyboard-runtime.md)。独立编辑器和 C#／C++ SDK 放到下一阶段；这里的“脚本”是描述演出的数据，不执行程序。

## 1. 先做哪几种效果

第一支原创样片建议用 12–18 秒：一张暗底图、一张标题图、不对称光带和三张序列帧。没有编译器或编辑器也能手写。先让谱师在高密度谱面里实打，再看独立演出或录屏；后两种视图看起来好，不代表游玩时读得清。

| 样片 | 实际想看到什么 | 用哪些基础能力 |
| --- | --- | --- |
| **标题入场** | 标题从左侧画外滑入，减速停在外场。先停稳一会儿，再淡出，不能因为移动结束就消失。 | `sprite`、`active`、`position`、`opacity`、命名缓动 |
| **外场脉冲** | 两侧灯带分拍点亮。光带沿一条边向外长开，亮度先升再降；同一组稍微旋转，左右元素一起跟着动。暗底可见，按键、判定线和 Mixer 路径仍清楚。 | `group`、`pivot`、`scale`、`rotation`、`tint`、`add`、拍绑定 |
| **局部符号** | 一组手绘符号按固定毫秒换帧，翻转后仍绕同一枢轴。最后一帧可保持，或按明确模式循环。把播放头拖回去，图案仍停在该时刻的那一帧。 | `sequence`、`flip-x`、`visible`、媒体时钟 |
| **跨 BPM 副歌** | 一段脉冲重复四次，变速后仍踩新的拍点；作为图片摆放的歌词保持在人声原处。 | `clip` / `repeat`；`clock="bar"` / `clock="media-ms"` |
| **外场分屏擦入** | 暗底上拉出一条渐变边框，光带从边框一侧进入，只在窗口内可见；裁切随窗口组转动。 | `shape`、`linear-gradient`、`clip-rect` |
| **曲线掠过与图集切换** | 一个符号沿弧线掠过，保持原本朝向；到第二个拍点切换图集帧，不抖动、不采到相邻图块。 | `path`、`region`、`sequence`、`sampling` |

这六个画面都在首轮内评审。解析原型先打通一张图，接着加功能并立即看样片，不必等所有指令设计完才开始。摄像机、通用粒子模拟和文字排版先不作为播放器指令。

## 2. 指令和数据结构

### 2.1 首轮候选

采用“**对象 + 显示区间 + 强类型属性轨**”。`Fade`、`Move`、`Rotate` 不分别占一套语法：它们只是对 `opacity`、`position`、`rotation` 的轨道采样。这能保留 osu! 的表达力，又不必为平移 X、平移 XY、瞬间改位各发明一种命令。C#／C++ 以后可以在 SDK 里提供这些便捷方法，展开成现有轨道。

| 构成 | 建议进入首轮的内容 | 决定它画什么 |
| --- | --- | --- |
| 头部与素材 | `storyboard 0`、`backdrop mode="keep"` 或 `backdrop mode="replace" color="#10131A"`、`asset <id> file=…` | `0` 是开发格式。默认保留原背景；`replace` 是整场演出的不透明底色，未指定颜色时为 `#10131A`。演出成功挂载才换底，空档也不会恢复原背景。单文件一场演出，素材按 ID 引用。 |
| 对象树 | `sprite`、`group`；稳定字符串 ID；同级 `order` | 精灵是图；组是局部坐标系和排序单元。组首轮不接收混合、整体透明度或滤镜。 |
| 出现时段 | `active from=… until=…`；对象声明自己的时间基准或继承 | 左闭右开 `[from, until)`，且 `from < until`；精灵和形状必须显式写。组可以不写，写了只裁它的子树，不改变子节点的时间原点；片段的区间由 `at`／`duration` 和重复规则决定。 |
| 属性 | `base <property> ...`；`track <property> { key … }` | `base` 写静态值。`track` 写有时间的变化。可只写其中一个，也可同时写。属性名来自固定表，不是引擎节点字段路径。 |
| 序列帧 | `sequence mode="once-hold" / "loop" { frame … }` | 精灵用图像素材或一组帧，二选一。每帧显式引用素材、写持续毫秒；帧内没有动作。 |

`position` 和 `scale` 保留双轴独立能力，但**同一个分量只有一个写入来源**。每种属性在格式里只有一个规范名称，调用端若想实现 `moveX()` / `moveY()`，可以在作者工具内组成两条分量轨。

| 属性 | 值、缺省与可用对象 | 画面规则 |
| --- | --- | --- |
| `position.x` / `position.y` | 有限逻辑像素，默认 `0,0`；组、精灵 | 位置是枢轴在父坐标里的落点，X 向右、Y 向下；允许画外。 |
| `scale.x` / `scale.y` | 有限非负倍率，默认 `1,1`；组、精灵 | `0` 把该轴压成零；`2` 放两倍。不用负数兼作镜像。 |
| `rotation` | 有限角度（度），默认 `0`；组、精灵 | 正值顺时针，绝对角度不取模。`0 → 360` 是完整一圈；`350 → 10` 按数值逆转 340°，想顺转 20° 应写 `350 → 370`。 |
| `pivot` | 静态 `(u,v)`，两值在 `[0,1]`，精灵默认 `0.5,0.5`；组不设此字段 | 精灵源图矩形左上 `(0,0)`、右下 `(1,1)`，可以把灯条定位在边缘；组原点就是组的局部零点。首轮不动画枢轴。 |
| `opacity` / `tint` | 透明度 `0…1` 默认 `1`；染色 `"#RRGGBB"` 默认白；仅精灵 | 透明度乘源 Alpha；染色乘源颜色，不覆盖原图明暗、不改变 Alpha。需要变成纯剪影时可染黑；想换色应选灰度或白色素材。 |
| `visible`、`flip-x`、`flip-y` | 布尔值；默认显示、默认不翻转。组只支持 `visible` | 离散轨按键跳变，不插值。翻转只作用于自身几何，沿穿过枢轴的局部轴镜像，不改位置、层或别的对象。 |
| `blend` | 静态 `"normal"`（默认）或 `"add"`；仅精灵 | `normal` 做普通透明合成；`add` 按源 Alpha 加光，不拿黑色盖住背后。不提供加色可动画、Multiply、Screen 或着色器，除非样片提出具体需要。 |

按 `world = parent × translate(position) × rotate(rotation) × scale(scale)` 得到变换；绘制精灵时先将源图坐标减去枢轴，再按 `flip` 翻本地轴。祖先组不可见时，整棵子树不画；节点不继承父级 tint、opacity 或 blend。若要让一组图像像一张图那样一起淡出，直接把各精灵都降透明度与“先把组画到离屏再整体淡出”并不等价；首轮不把这两个行为都叫 `group opacity`。

**先定清轨道边界：** 同一属性的键严格递增；同刻重复或同时出现两条相同属性轨，整份脚本报错。第一键之前用 `base` 或表中默认值；精确踩到键时用该键的值；末键之后一直保持末值，直到对象退出。用前一个键的 `ease` 描述它到下一键的插值；一次瞬变写 `step`，不用复制同刻键。首批缓动建议 `step`、`linear`、`sine-in`、`sine-out`、`sine-in-out`，缺省固定为 `linear`（布尔轨固定为 `step`，其余插值报错）。同一词的曲线公式不能随库升级改变；例如 `sine-out(u)=sin(πu/2)`，`sine-in(u)=1−cos(πu/2)`，`sine-in-out(u)=(1−cos(πu))/2`，其中 `u∈[0,1]` 是该段自己的时间进度。末键没有出向段，规范输出不写 `ease`，建议首版对无效 `ease` 报错。

### 2.2 同一轮扩展：按效果实现，不一次接完

| 批次 | 指令／属性 | 画面作用 |
| --- | --- | --- |
| A1 · 一条链跑通 | `asset`、`sprite`、`active`、`base`、`track`、`key`；媒体毫秒、基础位置与透明度、`step`／`linear`／`sine-out`、普通混合 | 一张标题在真实游戏里移入、停留、淡出，同时验证坏脚本不影响游玩。 |
| A2 · 时间和编组 | `group`、`clock="bar"`、`clip`、`repeat`；其余基础变换、显隐、翻转、完整 Sine 族、Quad 族与 `add` | 一组灯光跨 BPM 重复，能在任意时刻重新求值。 |
| A3 · 构图和图像 | `region`、`sequence`、`sampling`、`shape`、`linear-gradient`、`clip-rect`、`path` | 图集换帧、可旋转的擦入窗口、沿曲线路径飞行。拆成小样逐项接线。 |

以上都属于首轮范围，不是以后才考虑的候选项。验证器只接收当前构建已经能播放的指令；不能出现“已解析、渲染时静默跳过”的半成品。A1/A2/A3 只是开发顺序，不对应三套公开版本。

#### `clip` 与 `repeat`：一个时间片段装多个对象

- `group` 只改变子对象的空间和排序。`clip "id" at=… duration=…` 则把它放在父时间轴上，子节点从局部 0 开始写 `active` 和 `key`。`at`、`duration` 都用继承的时钟；拍片段用有理数，毫秒片段用整数。`clip` 不是可绘制节点，没有自己的变换；整体移动用内层 `group`。
- `repeat count=N period=…` 写在 `clip` 内。`N` 是**总播放次数**，包含第一次且为正整数。`period ≥ duration > 0`，不允许实例重叠；不写 `repeat` 就播一次。第 `i` 次起点是 `at+i×period`（`i` 从 0 起），窗口为 `[起点, 起点+duration)`，间隙不画，最后一轮没有额外的尾部空档。`period=duration` 时，边界直接回到下一轮的局部 0。第一轮只做从头重播，不把局部倒放和帧序列的交互一起引入。
- 首轮 `clip` 不嵌套。子键须处在局部范围内；子 `active` 不得跑出片段范围，结束键可等于局部结束。父组仍可裁短可见区间，不会改变各次起点。重复实例的诊断身份可用 `(clip ID, 第几次, 子对象 ID)`；脚本里不用手写复制后的 ID。
- `sequence` 依旧按媒体毫秒换帧。在按拍重复的某一轮中，先将“该次片段起点 + 精灵的局部出现点”换到绝对媒体时刻，再计算帧经过时间。每轮重新从第 0 帧开始；拍速变化只影响出现点和外层生命周期，不改变每帧固定时长。

#### `region`、形状、渐变、裁切与路径

| 指令／属性 | 关键参数与约定 |
| --- | --- |
| `region "id" asset="sheet" x=… y=… width=… height=…` | 图集左上角起算，整数像素，`[x,x+width)×[y,y+height)`，尺寸为正，超出原图拒绝。`sprite` 的素材引用及 `frame` 均可指向整图或 `region`；枢轴相对于裁出的矩形。同一序列的可见帧尺寸必须相同。`asset` 与 `region` 共用唯一的图像引用 ID 空间；`region` 只引用整图，不允许裁上再裁。 |
| `sampling` | 精灵的静态 `"linear"`（默认）或 `"nearest"`。图集在线性采样下不能读到相邻块；用图集裁边样片验证。第一轮不定义缩小用 mipmap 的效果。 |
| `shape "id" kind="rect" width=… height=…` | `rect` 和 `ellipse`，宽高为正逻辑像素；椭圆内接其局部矩形。枢轴、变换、染色、透明度、排序和混合沿用精灵的定义；不接 `sequence` 或 `sampling`。不写填充时是白色，`tint` 可改成纯色。 |
| `linear-gradient`（`shape` 内） | `from-x/from-y/to-x/to-y` 用形状矩形的归一化坐标，起终点归一化距离至少为 `0.000001`；沿两点连线投影到 `0…1`，超出两端保持端色。`stop at=… color="…"` 严格递增且包含 0 和 1；当前 512 样点实现要求相邻色标至少相隔 `1/511`（更窄请使用图片），颜色允许 `#RRGGBB` 或 `#RRGGBBAA`，RGB 和 Alpha 各自按第 4 节的色彩规则插值。渐变是静态填充，能随形状变换；首轮不单独动画色标。 |
| `clip-rect x=… y=… width=… height=…`（`group` 内） | 组局部坐标的矩形，宽高为正逻辑像素。角点随组旋转和缩放；不是全局轴对齐包围盒。只裁渲染输出，不改变时间、提示或输入；多个祖先裁切取交集。精确边界的像素容差另测。 |
| `path`（可绘制对象或 `group` 内） | 用带 `at/x/y` 的位置键；段首键可选出向控制点 `c1-x/c1-y/c2-x/c2-y`，四项齐备时按三次贝塞尔取位置，省略则直线。点和控制点都在父坐标系；`ease` 改的是曲线参数进度，不保证匀速走过等长距离。`path` 同时写两轴，按键期外的默认及持有规则与轨道相同；禁止再写两轴的 `track`，允许用 `base position.*` 指定首键前位置。不自动转向，朝向仍由 `rotation` 控制。 |

Quad 族加 `quad-in = u²`、`quad-out = 1−(1−u)²`、`quad-in-out`（前半 `2u²`，后半 `1−2(1−u)²`）。首轮不加有超调的曲线；日后加 `elastic` 或 `back` 时先定清越界透明度和非负缩放怎样处理。

### 2.3 留到样片之后

- 可复用的命名片段、嵌套循环、乒乓时间、更多形状和渐变可继续加；先确认 `clip`、遮罩和 `path` 的游玩效果，以及这些简写适不适合由工具生成。
- 字体排版、Alpha 遮罩和整组合成、程序粒子、视频和独立音轨需要各自的素材与渲染合同。首轮标题与歌词先用原创图片，粒子可用图集和路径组合。
- 实战命中触发、摄像机、前景覆盖另议。前两者要先约定回放、跳转和同刻顺序；任何演出都不修改真正的镜头、判定、HUD 或输入。

## 3. 文本长什么样

用 [KDL 2.0](https://kdl.dev/spec/) 的小子集，文件扩展名先用 `.uvsb`。大括号表示对象层级；参数写名字；时间轨一行一个键。**KDL 已定；接下来选的是读法和实现，不再比较 JSON。**

首轮子集：UTF-8；简单节点名和键名、双引号字符串、普通十进制整数与小数、`#true` / `#false`、`//` 注释、大括号与换行或分号。`storyboard 0` 必须是第一条且只出现一次；注释可以写在前面。先不接类型注解、`null`、特殊数字、多行字符串、斜杠删除注释或文件引入。UV 要在解码时拒绝重复命名参数；KDL 通用规则可以保留最后一个值，因此只有覆盖后的字典不能用来做 UV 验证。如果候选库拿不到原始条目、源位置或不便在构建节点树之前限制资源，就用只识别该子集的小型读取器，不退回另一种格式。

```kdl
storyboard 0
asset "title" file="assets/title.png"
asset "bar-light" file="assets/bar-light.png"

// 标题锁定录音位置，拍速怎么改都不动。
sprite "chorus-title" asset="title" clock="media-ms" order=10 {
    active from=16000 until=18300
    base "position.y" 300
    base "position.x" -180
    base "opacity" 0
    track "position.x" {
        key at=16000 value=-180 ease="sine-out"
        key at=16600 value=420
    }
    track "opacity" {
        key at=16000 value=0
        key at=16300 value=1 ease="step"
        key at=17800 value=1
        key at=18300 value=0
    }
}

// BarTime 8 至 8+1/4，跨 BPM 时按拍取值。
group "rim" clock="bar" order=20 {
    base "position.x" 960
    base "position.y" 540
    sprite "left-light" asset="bar-light" order=0 {
        active from="8" until="8+1/4"
        base "position.x" -620
        base "pivot" 1 0.5
        base "blend" "add"
        base "tint" "#63B8FF"
        track "scale.x" {
            key at="8" value=0.2 ease="sine-out"
            key at="8+1/8" value=1
        }
        track "opacity" {
            key at="8" value=0.6 ease="sine-out"
            key at="8+1/4" value=0
        }
    }
}
```

下面这段可接到上例的 `asset "bar-light"` 后面。同一扇窗口每四分之一小节打开一次，灯条只显示落在窗口内的部分：

```kdl
clip "shutter" clock="bar" at="8" duration="0+1/8" order=30 {
    repeat count=4 period="0+1/4"
    group "left-window" {
        base "position.x" 160
        base "position.y" 250
        clip-rect x=0 y=0 width=320 height=48

        shape "window-bg" kind="rect" width=320 height=48 order=0 {
            active from="0" until="0+1/8"
            base "pivot" 0 0
            linear-gradient from-x=0 from-y=0 to-x=1 to-y=0 {
                stop at=0 color="#123351FF"
                stop at=1 color="#12335100"
            }
        }
        sprite "sweep" asset="bar-light" order=1 {
            active from="0" until="0+1/8"
            base "pivot" 0 0
            path {
                key at="0" x=-80 y=0 c1-x=0 c1-y=-20 c2-x=160 c2-y=20 ease="quad-out"
                key at="0+1/8" x=320 y=0
            }
        }
    }
}
```

- `media-ms` 是从录音样本起点计的非负整数毫秒，`bar` 是 UV 的精确 `BarTime`；以 `"8"` 或 `"8+1/4"` 表示约分后的混合分数。顶层对象必须写 `clock`，子节点继承且不能切换。没有 `clip` 时 `active` 与 `key` 用录音或谱面的绝对坐标；在 `clip` 下改用片段局部坐标，时钟单位不变。`group` 自身不平移时间。媒体时间戳虽是整数，运行时取样不先四舍五入到毫秒。
- 帧序列从精灵自身出现点折算出的媒体时刻开始，只换图，不写别的属性。同序列图片须同尺寸，每帧时长为正整数毫秒；按累计帧时长取 `[frameStart, frameEnd)`。`once-hold` 播完停在末帧；`loop` 取总时长余数。父组裁掉前段或用 `visible` 暂时隐藏时，序列仍按原点计算。改变 BPM 可能移动第一帧的媒体起点，但不会把每帧的 80 毫秒拉长。精灵用 `sequence` 时省略 `asset=…`，每帧的 ID 仍须在素材表声明：`sequence mode="loop" { frame "ring-0" duration-ms=80; frame "ring-1" duration-ms=80; frame "ring-2" duration-ms=80 }`。
- 键可落在精灵 `until` 边界上，作为最后一个出场段的目标；处在该时刻不能再看见精灵。建议键不越出**自身**已声明的区间（组裁切不是自身边界）；范围或单位错了直接报错。没有 `NaN`、无限值、模糊数字或隐式秒／拍转换。
- UTF-8，固定一种规范排版；字符串 ID 按序数比较，区分大小写，只允许一份文档内唯一的对象 ID。资源依赖仅从包内素材表枚举，不递归扫描整个包。初期禁用 `include`、任意表达式和宏。素材路径相对脚本，且仍须处在演出目录授权的包根范围内；拒绝绝对路径、`..`、外链和大小写碰撞。
- ID、属性名与源位置进入验证诊断，例如 `UVSB041: left-light / opacity 第 2 键与前一键同刻`。格式化相同语义不改变画面；编辑器以后可以另做保注释的作者文件往返，游戏端只消费规范化数据。

### 开发期间怎么改

目前只有 `storyboard 0` 一套开发合同。不做迁移、不做旧指令别名、不预留 `requires`。需要改旧指令时，同一个提交更新规格、手写样片和参考结果；不修订某个数值只是为了迁就一个实现 bug。未知指令、重复键、错参数、尚未接渲染的指令都要给出明确错误；游戏不能静默漏画。公开前根据已验收效果再冻结第一版、决定版本识别和升级策略。开发草稿不拿去当公共谱包发行。

## 4. 游戏必须画成什么样

### 放在哪一层，什么时候求值

阶段 A 只有一个由游戏托管的 Storyboard 插槽：**原游戏背景在后，演出在中，判定线、Note、必要玩法提示、HUD、暂停和结算都在前。** 脚本中的 `order` 只排 Storyboard 内部；同级按 `(order, ID 的序数顺序)` 从小到大向前绘制，`order` 是整数，默认 `0`。一个组作为整体入列，组内排序不能越过兄弟组。画面使用固定 1920×1080 逻辑内容区、等比黑边；对象可以从画外进场，绘制裁在内容区，不延到黑边。不把这些坐标接成共享舞台内部的 Y 偏移，不让 Mirror 反转文字。需要检查实际 [Gameplay 舞台分层](../client/scripts/game/gameplay/GameplayMain.Presentation.cs#L43-L63)，不能仅凭节点名假定插入位置正确。

开局读取当前差分对应的脚本，一次解析和校验。每次绘制，用当前**未叠加玩家判定校准**的媒体时刻求全部可见状态；按拍对象复用[谱面 BPM 与偏移换算](../shared/Chart/V2/Evaluation.cs#L16-L88)。按拍轨跨 BPM 要以当前 `BarTime` 算插值进度，不能只把两个端点先换成毫秒再做一次线性插值。暂停只冻结，继续从同处求值；向前拖、倒拖和离线录制取同一时刻的值。限于录音存在的播放区间：不相交的演出不显示，不延迟结算，不改变 BLEED 失败当帧行为。

### 透明、加色与低动效

候选参考色规则：PNG 和调色字面量以 sRGB 表达 RGB，染色插值/相乘、正常混合与加色的参考计算在线性光进行，Alpha 独立。若源像素的线性 RGB 为 `S`、染色为 `T`，令 `a = textureAlpha × opacity`、`c = S × T`。对不透明背景 `D`，普通混合为 `a × c + (1−a) × D`；加色为 `D + a × c`，在最终显示的 SDR 参考上限裁切。要用实际 Godot 游戏合成做参考图；如果当前管线与候选差异明显，**在 v1 冻结前**决定支持的效果或裁掉 `add`，不要发布后在不同平台替换语义。固定点验收先比较无缩放纯色块和 Alpha，纹理采样／边缘容差另测。

保留玩家控制权：Off 无需解码演出素材，仍有原游戏背景；Full 使用校验过的演出；Reduced v1 建议优先接审核过的独立静态替代，否则不播放该演出。不要用“把所有动画乘 0.4”当作闪变修复。不许用脚本命令去覆盖玩家动效选项；本地坏附件退回原背景并诊断，发布和明确含演出的录制不能静默通过。怎么在 Windows、Android 和商店分别验收，见[独立编辑器方案](storyboard-editor-plan.md)。

### 有哪些可复核的检查

| 检查 | 给定输入和应看到的结果 |
| --- | --- |
| 时间边界、基本插值 | 标题样例在 15999 ms 不存在；16000 ms 开始，`opacity=0`；16200 ms 的 `position.x = 120`（区间三分之一，`sine-out=0.5`），`opacity≈0.667`；16600 ms `position.x=420`、`opacity=1`；18300 ms 整个精灵不参与绘制。先从头播到该点，再直接跳过去比较。 |
| 旋转、枢轴、翻转 | 取一张宽 100、高 40 的自制图，枢轴 `(0,0)`、位置 `(100,100)`。右上角开始位于 `(200,100)`；顺时针 90° 后变为 `(100,200)`。重置角度后只打开 `flip-x`，该角变成 `(0,100)`，枢轴仍在 `(100,100)`。再套一个旋转父组检查叠加顺序。 |
| 帧序列 | 三帧每帧 80 ms，局部 79 ms 是第 0 帧、80 ms 是第 1 帧；240 ms 在 `once-hold` 为第 2 帧，在 `loop` 回到第 0 帧。窗口关闭后都不显示。 |
| 颜色和遮挡 | 参考例：线性灰背景 `D=0.2`、`c=0.4`、`a=0.5`，普通结果 `0.3`，加色 `0.4`（转换成显示 RGB 前）。高密谱上同时看三面 Note、判定线、Mixer 和暂停 UI；背光不能淹没必要信息，不能吞触控。 |
| 跨速度和校准 | 在 BarTime 8 为 120 BPM，8+1/8 切 180 BPM。灯带从 8 到 8+1/4 共约 416.67 ms；到变速边界时已走完这条按拍轨的 50%，不是媒体时长的 60%。媒体秒标题不移动。另改玩家校准，核对演出仍在原录音位置。 |
| 重复与空档 | 扩展样例在 BarTime 8、8+1/4、8+1/2、8+3/4 进入局部 0。8+1/8 正好停止第一轮，间隙不画，8+7/8 结束最后一轮。倒拖回 8+1/4 应得到刚进入第二轮的同一状态。再用 `period=duration` 测连续边界不双画。 |
| 路径与裁切 | 前后键位置为 `(0,0)` 和 `(100,0)`，线性时间，控制点为 `(0,100)`、`(100,100)`。半程是 `(50,75)`，图案朝向不变。另给矩形组旋转 30°，对照内外各一点；不能只按世界坐标的矩形包围盒裁切。 |
| 图集和渐变 | 用相邻纯红／纯蓝图块验证边缘不串色；线性与最近邻对照。黑白不透明渐变的中点为线性亮度 0.5，而不是 sRGB 编码值 0.5；透明端验证不会涂黑原背景。 |
| 错误和回退 | 重复命名参数、重复键、未知节点、缺图、路径越界、错误单位分别造一份；不得留下半个演出。对照无附件、Off、坏附件与正常附件，谱面 Gameplay Digest、输入和成绩流程不变。 |

保留两种基线：**指定时刻求到的对象／值**用于精确回归；**真实游戏的代表帧与一段播放**用于看音乐感、色彩、遮挡与读谱。实现可以从简单的区间筛选开始，后续再优化索引、合批和缓存。未实测前不写 Android 性能结论，也不以固定帧完全等同于真机体验。

## 5. 游戏舞台怎样接第一版解析

第一条链路用 **A1 的标题样片**：选中测试差分 → 读它显式绑定的 `.uvsb` → 验证整份演出与素材 → 创建舞台节点 → 随歌曲取样。先不做全曲库扫描、作者编辑器、SDK、脚本自动热重载或缓存。开发原型用本地测试绑定，将一份文件映射到明确的 `packId + chartId`；不靠文件同名推断，不把临时加载规则变成公共谱包合同。

| 落点（拟议） | 负责什么 | 不负责什么 |
| --- | --- | --- |
| `shared/Storyboard` | KDL 子集读取、源位置、强类型解码、引用校验、时间与场景求值。输入是受限文本和已有 BPM 时间线；输出是可按时刻取得的有序绘制项。 | 不读 Godot 路径，不加载贴图，不碰判定、计分或全局设置。 |
| `presentation/game/storyboard` | 根据已解析对象、纹理和每帧状态画普通精灵；再加加色、形状、裁切等适配。保持独立的演出根节点。 | 不读包、不解析 KDL、不再采音频时钟、不把作者 `order` 转成跨舞台的 Z。 |
| 游戏 `GameplayMain` 周边 | 按已加载差分绑定测试附件、处理媒体与失败回退，挂载绘制根、传媒体采样、离场释放。 | 现有 Note、输入、判定、音轨结束和结算流程仍由原调用方负责。 |

1. **读和验分开。** 先解析带源位置的节点与原始参数，再转成强类型模型。拒绝重复参数、未知指令、未知属性及参数数量不符；校验 ID、区间、时间单位、引用、数值和可播放能力。读入前设字节和 UTF-8 限制；解析中要限制深度、节点、键和重复量，解码前查路径和纹理尺寸预算。错误显示文件、行、列、对象 ID 和原因。开发原型一旦有错就不挂载整份演出，不要把坏文件解析成空场景后报成功。
2. **先窄接本地资源。** A1 只读取主动指定的测试文件和原创 PNG；解析阶段不访问路径。客户端资源适配根据验证后的素材表读取。普通本地目录与以后受控 `res://` 的入口分开；后者需走 Godot VFS。[现有交接的加载边界](handoff.md#22-谱面判定与存档的重要边界)仍有效。结束、重开和换曲都由本局释放演出资源，避免残留上一曲的图。
3. **确认真实绘制夹层。** 现有[舞台初始化](../client/scripts/game/gameplay/GameplayMain.Presentation.cs#L43-L63)将背景、判定线所在的舞台与 HUD 分开，舞台还带 `StageOffsetY`。[背景和线的创建](../presentation/game/GameplayStageRenderer.cs#L82-L99)及[Chrome/Note 子层](../presentation/game/GameplayStageRenderer.cs#L172-L197)说明背景和判定线目前同属 Chrome。原型应通过明确的宿主绘制顺序把 Storyboard 放在两者之间；不能假设加一个同层兄弟节点就会正好夹进去。若挂在带偏移的舞台根，适配器须抵消舞台局部偏移，让脚本 `(0,0)` 对齐逻辑内容区。用覆盖边界的大色块和三轨同帧图验证顺序与坐标，保持无脚本时原画面不变。
4. **同一帧读一次媒体时刻。** 现有[主循环](../client/scripts/game/GameplayMain.cs#L250-L286)一次读含玩家校准的 `t`；[SongClock](../client/scripts/audio/SongClock.cs#L148-L176)最后才叠加校准。建议在同一次采样里返回未加校准和现有判定用时间，不能从两个调用分别读播放器；原校准值、固定帧与暂停行为要逐项回归。A2 的按拍取样可用当前差分的 [`LoadedChart.V2Timeline`](../client/scripts/game/charts/ChartPack.cs#L57-L75)，不拿渲染 Note 用的校准后 `currentBar` 顶替。没有严格 v2 时间线的附件若使用 `bar`，原型明确不支持，不猜延伸规则。自然播完后停止取样并隐藏，不借成绩结算的补时继续播。
5. **先检验 A1，再轮流接 A2 和 A3。** A1 用同一份脚本做纯 C# 解析夹具、按时刻的状态检查及 Windows 游戏画面。A2 验证变速、循环边界和组变换；A3 建旋转裁切、渐变和图集边缘的独立样片。有些效果需要改绘制方式，可以换实现，不用一开始构造优化版渲染器。暂不以构建成功代替实打，也不在编辑器独立预览里替代游戏验收。

首轮只验证受控本地附件和实际画面；不改现有 v2／v2.1 合同、Gameplay Digest、制谱器写包、录制文件收集、Android 或商店发布规则。等手写样片走通，再决定正式绑定及作者工具如何生成同一份 KDL 数据。
