# 谱面格式 v2.1：自定义出向曲线

v2.1 沿用 [v2.0](chart-format-v2.md) 的包结构、精确小节、BPM、判定时间和计分规则。变化只有两处：包与差分能声明次版本；Scroll、Hold、Mixer 的出向曲线能写数学表达式。机器合同见 [2.1 Schema](../schemas/chart-format-v2.1/)，可直接用制谱器打开[混合版本示例包](../schemas/chart-format-v2.1/examples/mixed-pack/)。这是原创静音测试包，其中 `baseline` 是普通 2.0 差分，`rebound` 展示回弹和分数次幂。

## 文件怎么写

- `formatVersion` 仍是整数 `2`。没有 `formatMinor` 就是 2.0；声明 2.1 时写整数 `"formatMinor": 1`，不写 `2.1`、`"2.1"` 或显式 `formatMinor: 0`。不支持的次版本不得按旧版尝试播放。
- 含 2.1 差分的包头也须声明 2.1；2.1 包可以含未升级的 2.0 差分。旧游戏不能打开声明 2.1 的包，即使其中有普通差分。
- 只有非尾 Scroll 事件、Hold/Mixer 的头和非尾节点能写 `curveToNext: "custom"`，并且必须同时写非空字符串 `customExpr`。内置曲线、普通音符和尾点都不接受该字段。内置曲线含义不变，`smooth` 仍是路径专用。

例如从这一点到下一点先越过目标，再回到终点：

```json
{
  "time": { "bar": 2, "numerator": 0, "denominator": 1 },
  "value": 1.0,
  "curveToNext": "custom",
  "customExpr": "1 - (1-t)^1.5 * cos(3*pi*t)"
}
```

## 公式和数值

`t` 是这一段已经走过的小节比例，不是音频秒数。已知精确小节时，先在有理数域做 `(bar-start)/(end-start)`，最后才转换成 binary64。`p=f(t)` 是进度。Scroll 按它插值倍率，Hold/Mixer 按同一个 `p` 分别插值中心与宽度。公式不能读取其他音符、帧率、系统时间或文件。

| 写法 | 约定 |
| --- | --- |
| `t`、`pi`、`e` | 标识符区分大小写；函数只认下表中的名字。 |
| 数字、`+ - * / ^`、括号 | 小数点用 `.`，可写科学计数法；必须显式写乘号。`^` 表示幂，右结合，优先于一元负号。`-t^2` 意为 `-(t^2)`。支持非整数幂。 |
| `sin(x)`、`cos(x)`、`exp(x)`、`log(x)`、`sqrt(x)`、`abs(x)` | 三角函数用弧度，`log` 是自然对数。 |
| `min(a,b)`、`max(a,b)` | 都取两个参数；没有变量赋值、循环或宿主代码执行。 |

端点的绝对容差为 `1e-9`，用来容纳例如 `sin(pi)` 的数值尾差。通过检查后，两个端点固定为恰好 `0` 和 `1`。这项容差不用于吞掉小节差、不合并相邻节点，也不用于放宽 `width > 0` 或 `0 < scroll ≤ 64`。允许进度回摆、低于 0 或高于 1；如果过冲导致实际倍率非法、实际宽度非正或几何不再有限，整段无效。轨道推荐坐标 `[0,5]` 不是禁止越过的几何边界。

## 预览和游戏使用哪条线

保存原公式，不保存采样点或生成的音符。共享编译器把公式转换为有序折线，**折线是 2.1 的游玩形状**。它从端点开始，以二等分区间逐段检查定义域，并用保守值域或斜率界约束公式与弦的误差；不能证明或细分超出预算就拒绝。归一化进度的绝对误差目标是 `1e-4`，不是 `0.0001` 小节、毫秒或像素。每条折线最多 2048 段。表达式源码最长 1024 个 UTF-16 码元，语法最多 128 个节点，嵌套上限 32。运算不是无限精度 CAS，例如表达式即使数学上有意义，也可能因无法在预算内确认精度而被拒。

折点之间按线性插值。预览曲线、Scroll 查询、路径求值和游戏接触共用这一结果；到真实控制点直接取该点自身的值。画长条时还要在段内的 BPM 变化处分开，避免在秒域画直线而判定在小节域插值。新折点不是作者节点，不产生额外 Hold 判定、Mixer tick、选择手柄或横向描边。含自定义段的 Hold 和 Mixer 都按路径边界与接触位置的交点回放帧内变化。即使手指没动、路径在同一帧内移出又移回，也按实际出入时刻处理。Hold 把触点宽度计入覆盖，并从首次失联时的 BPM 冻结宽限；Mixer 仍按接收器位置判覆盖，用 1/8 小节宽限。两者不共用判定窗口或计分规则。

折线算法本身属于规则集，**新版实现不能只达到同一个误差限就任意换一条折线**。数值候选须通过[逐位已知答案](../tools/core-tests/Charts/CustomCurvePrecisionTests.cs)、[接触与粗细帧回放](../tools/core-tests/Charts/CustomCurveRuntimeTests.cs)。包内重复引用也有总量限制，见[共享验证器](../shared/Chart/V2/CustomCurveValidation.cs)。超过预算报错，不截断公式或丢掉后半条路径。

## 保存、载入和成绩

制谱器保留公式原文。有效草稿应用后可撤销。TIMING 面板的「新增」可用当前字段建另一条 Scroll 事件，但不会替原事件应用或清除草稿。改差分 ID 后仍可在原谱点继续编辑；复制的差分不继承原件的未应用草稿。写盘前还要校验端点、目标几何、所有差分以及包头版本。只有过冲警告时能保存；有错误或未处理的公式草稿时不会用旧值覆盖文件。第一次需要升级包时会提示对方也要更新游戏。手写谱不经过编辑器，游戏加载器及商店审核仍须执行相同的严格校验。

2.1 差分使用 `dynamite-uv-ruleset-2.1`，继续使用 `gameplay-v1` 的 JCS/SHA-256 流程。每个自定义段的玩法投影含 `curveToNext: "custom"` 和规范化表达式：忽略空白、冗余分组，数值用不依赖区域设置的往返表示；不尝试判定任意两个代数式等价。包头的次版本不替代差分的规则集。普通 2.0 差分仍使用 `dynamite-uv-ruleset-2.0`，在混合包里也不会清空旧 BEST。自动验证、原生运行、候选包身份与尚未覆盖的设备见[验证记录](verification.md)。
