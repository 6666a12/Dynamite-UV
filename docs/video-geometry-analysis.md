# Dynamix Universe 谱面几何参数：视频实测分析

> 数据来源：autoplay 全 PERFECT 谱面确认视频
> `gameplay_videos/[Dynamix Universe⧸谱面确认] Tablear GIGA 15.0 Ω.mp4`（1440×1080，30fps，187.6s）
> 谱面文件：`_rev/extracted/Charts/75f188871f8d_Map_0021.5 - Tablear [Giga].asset.json`
> 分析区间：视频 0–62s（抽帧 15fps，谱面 DropSpeed=1.0 全程恒定段）。
> 中间数据与脚本：`gameplay_videos/geo/`（`bars.json`、`bursts.json`、`lane_fit.json`、`clean_x.json`、`sidey_*.json` 等，均可由同目录脚本重跑生成）。

## 1. 方法概述

- 对抽帧逐帧做颜色阈值检测，提取两类图元：**横条**（center 下落的 note，青/绿色）与**竖条**（侧轨 note）；另检测命中瞬间的**白色星爆**区域（bottom / left / right 三个区域）。
- 用谱面 `Baked_Second` 作为精确命中时间，与视频帧时间对齐（确定全局时间偏移 OFF 后），把每个检测到的条/星爆归属到具体谱面 note，再做交叉验证（条的轨迹外推命中点须与星爆位置 ±40~50px 内一致才采信）。
- 坐标系：像素，原点左上，x 向右（0–1440），y 向下（0–1080）。f 序列帧号 f 对应视频时间 t = f/15 秒（已与 30fps 抽帧序列核对）。

## 2. 时间对齐

**视频时间 = 谱面 `Baked_Second` + 0.508s（OFF = 0.508 ± 0.03s）**

- 依据：380 个 lane 拟合条外推到判定线的时刻与谱面 `Baked_Second` 之差，各 Type 一致（0.508–0.510，std 0.025–0.034s）；侧轨独立验证 Right 0.507±0.035、Left 0.524±0.023。
- ⚠ 视频开头 **T < 2.165s 的前 6 个 center note 未渲染/未判定**（autoplay 起步漏过），combo 从 T=2.165 才开始计 1。复现器需注意视频前 ~2.7s 不能用于校验。
- 早期用星爆 onset 投票得到的 OFF≈0.604 是密集段白底抬升导致检测滞后，**作废**。

## 3. Center（底部下落轨）

### 3.1 运动方式

- **竖直下落，无透视、无横向漂移**：同一 note 各帧 xc 的 std 仅 1–4px。
- **速度 v = 1040–1065 px/s**（30fps 逐帧测得 35.4px/帧 = 1062px/s；谱面驱动拟合中位 1040px/s）。建议取 **v ≈ 1050 px/s**。
- **生成方式：条形在 y ≈ 300 ± 20 处淡入出现**（不是从屏幕顶端下落），约为命中前 0.52s；到达判定线即爆炸消失，**不下沉过线**。
- **判定线 y ≈ 857–858**：星爆 y 质心中位 858.1±7.1；判定线青色亮线位于 y≈853–865。

### 3.2 横向映射 x(P)——时变（重要）

x(Position) **不是固定曲线**：轨道整体平移/缩放是铺面演出手法（同一时间粉色 Mixer 条等 UI 静止不动，已排除相机移动）。谱面 JSON 中没有任何 lane/轨道事件字段，**这是本项目最大的不确定项**。

参考截面（t≈2–3.5s，条轨迹与星爆双重验证点）：

| P | 0.2 | 1.3 | 1.6 | 2.6 | 3.0 | 3.4 | 4.2 |
|---|-----|-----|-----|-----|-----|-----|-----|
| x(px) | 333 | 495 | 497 | 581 | 644 | 758 | 965 |

- 曲线**非线性**：左段平缓、右段陡。三次拟合（该截面）：
  `x = 16.34·P³ − 83.02·P² + 221.59·P + 295.06`（残差 std 14.4px）
- 全局线性近似（仅作粗估）：`x ≈ 275 + 144·P`（误差 ±85px）
- 其他时段该曲线整体平移 ±40–80px。同一 P=1.3 实测：t=2.2→495，t=6.3→415，t=33.6→427，t=49.3→496，t=52.4→375，t=60.9→347。

### 3.3 尺寸与外观

- W=1.0 的 Tap：**宽 ≈ 203–204px，高 ≈ 22–24px**，顶部中央有小凸 tab。
- 宽度换算：`w_px ≈ 204 × W` 有两个独立点支持（W=1.0→204；W=0.8→164–166，204×0.8=163 ✓）。其余 Width 样本不足，见 §7。
- 颜色无语义：条 hue≈187（青）或 ≈148（绿），按歌曲段落整体切换（t=20–40s 段偏绿），**与 Type 无关**；偶见黄色。

### 3.4 Hold（Type 3/4）

视频中表现为判定线上 x 对应位置的**持续辉光**（如 x≈413、678 处长亮条带），自 hold head 命中起持续到 tail；hold 本体条形未单独测量。

**渲染模型（玩家确认 + 谱面结构互证）**：Hold/Chain/Mixer 是**刚性形状**——
节点只是塑造形状的顶点，整个形状对着判定线匀速下落，过线部分被判定线
**连续裁剪吞噬**（不是节点锚定在判定线上、也不是到点才出现）。斜 hold 的
面板下缘会沿判定线连续滑动。社区版 MVP 已按此实现（GameplayMain 的
`PositionForRaw` + `ClipToLine`）。

## 4. 侧轨（Left / Right）

### 4.1 运动方式

- note 为**竖直条**，**从屏幕中央 x≈720 附近生成**（淡入点约 720∓64），以 **≈1010–1025 px/s 向屏幕边缘外移**（右轨向右、左轨向左，速度与 center 下落速度同量级），到达边缘判定线处爆炸。
- 实测速度：右轨中位 1021±83 px/s，左轨 1011±63 px/s。
- **命中点 x：右轨 = 1274.9 ± 8.8，左轨 = 164.9 ± 4.5**（1440 宽画面下基本对称，距边缘 ~165px）。
- 条尺寸（W=2.0 样本）：**长 ≈204px，厚 ≈17–24px**（含辉光），指向运动方向的端部为尖角。若 center 的 204px/W 成立，侧轨 W=2.0→204px 相当于 ~102px/W，单侧样本，存疑。
- 命中帧爆裂白球（x≈1276 附近）会覆盖竖条末端（x≈1200–1230），属正常特效遮挡。

### 4.2 纵向映射 y(P)——时变（与 center 同样的问题）

全局线性拟合完全失败（Left r²=0.009，Right r²=0.056）：**y(P) 随时间剧烈变化**，只能给局部快照（均为条轨迹外推命中 y 与星爆 y ±50px 交叉验证的点）：

| 时间窗 | 侧 | 快照 |
|---|---|---|
| t≈50.6–51.2 | Left | P=−0.4…3.5（8 点，Type 2 链）命中 y 全部 ≈ 724–735 —— 链路径近似水平直线 y≈733 |
| t≈27.3–29.6 | Right | P=0.4…2.9（9 点）y ≈ 460±25，几乎不随 P 变化 |
| t≈32.8–33.8 | Right | P=1.1→578，1.3→624，1.4→654，斜率 ≈ +250 px/P |
| t≈57.6–58.8 | 两侧 | P=1.5→532，P=2.0→533（平） |
| t≈59.7–61.4 | 两侧 | P=0.0→581，P=1.5→583（平） |

同一 P 在不同时刻的命中 y 可差 100px 以上（如 P=1.5：t≈29.5→469，t≈58.7→532）。多数快照窗口内 y 对 P 几乎是平的，个别窗口有明显斜率——疑似侧轨存在竖直方向的轨道移动/旋转演出，机制未明。

### 4.3 链缎带中心线测量与新假说：3D 隧道侧壁透视

对 L 链（8 节点，chart 24.74–25.28，P=−0.10…3.50）在 video 26.2s 的彩虹缎带做
高饱和像素骨架提取（`tmp_c/ribbon.py`），得到中心线（物理像素 @1440）：

- 缎带近端起于 **(219, 748)**，向右上延伸：(290,730)→(340,700)→(380,676)→
  (420,648)→(465,605)→(500,582)；
- **x>500 后缎带没入 Mixer 粉条区域（y≈634, x 506–933）消失**，而远端 4 个节点
  （时间间隔恒定 0.08s）若为平面匀速渲染，应位于 x≈523/599/675/751、间距恒定
  76px——实际在缎带掩码中完全找不到，唯一解释是它们被压缩进 (x≈650–750, y≈634)
  的灭点区域。

**假说**：侧轨是 3D 隧道的左右侧壁——note 沿侧壁向判定线"飞出"，在屏 y 由
`f(P)`（判定线上的真实高度）与深度共同决定：越远离判定线越被透视拉向灭点
（y≈634，即 Mixer 粉条高度≈地平线），节点间距也随之压缩。这能同时解释：

1. §4.2 的"y(P) 时变"乱象——旧测量混合了命中 y（真 f(P)）与轨迹 y（含深度透视）；
2. 缎带远端恒汇入 Mixer 条附近（与"链从 Mixer 条附近生成"的目击一致）；
3. §4.1 侧轨速度 1010–1025px/s 只是**近线表观速度**，远端表观速度更低。

对渲染器的含义：侧轨若要形似原版，需要透视外移映射（x、y 都是 rem 的非线性
函数，远端压向灭点），f(P) 真值只能取**命中时刻**的 y。待反编译代码确认
（`_rev/dotnet` 调查进行中）。

## 5. 侧轨滑链（Type 6/7）与 Mixer 粉条（Type 8/9）

- Type 6/7（**滑链**，P 链即路径）：渲染为**黄边竖直胶囊**（内芯白/粉），从 Mixer 条附近出发沿侧轨向边缘移动，**拖彩虹色缎带**连接下一段（88–89s 段实锤）。缎带的消耗方式为**连续吞噬**（玩家确认与原版一致）：整条链是刚性形状整体外移，过判定线的部分被连续裁掉，而不是逐节点整段消失。
- 粉色横条是**固定 UI**：y≈634（范围 606–650），x 506–933，中央 x≈710 有竖直光标；不随轨道演出移动。
- Type 9（Center，W=5.5，P=−0.25，出现于 T=8.66 / 9.897 / 19.794 / 34.639…）：出现时 Mixer 条上叠加**黄边青色高亮段**（f139、f390 可见）。t≈20.3s 处检查未见粉条显著异常（该次高亮或已结束），操作细节未深挖。

## 7. 不确定项清单

1. **x(P) / y(P) 时变成因不明**（最大问题）：谱面 JSON 无 lane 事件字段，曲线整体平移 ±40–80px（center）、侧轨 y 有时变平有时变陡。可能需要从游戏代码（`_rev/dotnet` 反编译）找轨道演出（lane move/scale）逻辑。
2. **Width→px 换算仅两点验证**（W=1.0、0.8）；W=1.4 等样本曾测出自相矛盾的值（数据脏），w=204×W 尚未全面证实。
3. **侧轨 Width 比例**：W=2.0→204px 仅一类样本，≈102px/W 还是非线性，未知。
4. **Type 5（Burst）Position 语义**未单独验证。
5. **Mixer 操作细节**（Type 9 高亮段的精确起止、缎带的连接规则）只做了目击级观察。
6. DropSpeed≠1.0 的段（BarTime 52.5 后）未分析，速度是否线性乘 DropSpeed 未验证。
7. 视频为 15fps 抽帧分析为主，y 向位置量化误差 ±8px 量级；星爆质心受 PERFECT 文字与常驻辉光污染时已用交叉验证剔除，但底部 y 620–830 区域的条检测本身不可靠。

## 8. 正式游玩视频对比验证（Charter 漂移是否真实）

> 新数据源：`gameplay_videos/tablear_realplay.mp4`（B 站 BV1NYC4BZEcs，1920×1080，30fps，190.5s），
> 真人玩家手元 AP（相机俯拍 iPad，双手入镜）。谱面不变，仍分析 DropSpeed=1.0 的前半段（谱面 T<55s）。
> 中间数据与脚本：`gameplay_videos/geo2/`（`bars2.json`、`bursts2.json`、`hitq2.json`、`globalfit2.json` 等）。

### 8.1 预处理

- 游戏画面四角（结算白屏帧拟合）：TL(473,196)、TR(1531,194)、BR(1535,999)、BL(474,1000)，透视矫正回 1440×1080 坐标系；再用 Mixer 粉条边缘（x 508/937 → 506/933）与判定线/粉条 y 锚点做残差仿射校正（x ≈ 恒等 ±4px；y 修正 ~0.933 缩放 +100 偏移）。边缘区域 x 残差不确定度约 ±25px（侧轨命中点测得 138/1302 vs 谱面确认视频的 165/1275，疑为矫正残差而非真实差异）。
- 时间偏移 **OFF′ = 3.811s**（条轨迹外推命中时刻 vs `Baked_Second`，426/564 note 匹配；真人手元残差 std 0.063s，含 15fps 量化与玩家抖动）。

### 8.2 渲染方式差异（重要背景）

实机画面是 **3D 隧道透视**：note 从上方灭点区域生成、向判定线加速下落（表观速度随深度增加，恒定速度模型不成立），但**下落过程中 x 基本恒定**（实测队列 x 漂移 <5px）。谱面确认（Charter）视频则是平面渲染、匀速下落。两者 x(P) 绝对曲线也不同（见 8.3），不能混用。

### 8.3 核心结论：实机 x(P) **不随时间漂移**

用命中星爆 onset 的 x 作为命中点（n>1500、x∈[300,1250]、|dt|≤0.07s 匹配谱面，迭代曲线一致性去重/去噪，锚点种子初始化）：

**全局拟合（谱面 2–55s 一段式）：249/308 note，r²=0.9968，残差 std 仅 14.3px，max|resid|=38.5px**

- 三次：`x = −2.54·P³ + 18.60·P² + 168.49·P + 326.14`
- 线性（几乎一样好）：`x = 312.5 + 204.9·P`（残差 std 15.6px）
- 参考点：x(0.2)=361，x(1.3)=571，x(2.0)=717，x(2.6)=845，x(3.0)=931，x(3.4)=1014，x(4.2)=1174

**漂移检验（对全局曲线的分窗残差）：**

| 窗口（谱面时间） | 2–15s | 15–30s | 30–45s | 45–55s |
|---|---|---|---|---|
| note 数 | 68 | 49 | 75 | 43 |
| 平均残差 | +0.7px | +0.9px | +2.1px | −3.2px |
| 残差 std | 10.4 | 17.3 | 12.3 | 18.6 |

同一 P 跨 53s 的重复测量更具说服力（原始星爆数据，未拟合）：

- P=1.3 → 570/551/570/572/573/574/575/581/568/572/576/570/572（T=2.2…53.5，**std ≈6px**）
- P=2.0 → 716/719/720/720/721/718（T=14.4…53.2，**std ≈2px**）
- P=3.0 → 930/934/928/936（T=2.8…54.9）

对照谱面确认视频同一 P=1.3：495/415/427/496/375/347（漂移幅度 ±80px，极差 149px）。

**结论：实机游玩中 x(Position) 是固定映射（漂移 <5px 量级，残差即测量噪声）；谱面确认模式的 ±40–80px（局部可达 150px）轨道平移是 Charter 预览特有的演出/相机效果，正式游玩不存在。**

### 8.4 其他一致性核对（归一化到 1440 宽后）

| 项目 | 谱面确认视频 | 实机视频 | 判定 |
|---|---|---|---|
| 判定线 y | 858 | 855–862 | 一致 |
| W=1.0 条宽 | 204px | 211±16px | +3%，矫正误差内，基本一致 |
| 侧轨命中点 x | 165 / 1275 | 138 / 1302 | 差 ±27px，疑为透视矫正边缘残差，不能定论 |
| note 颜色 | 青/绿按段落切换 | 全程青色系（部分链 note 偏 teal 绿） | 不一致（或本段未覆盖绿色段） |
| x(P) 曲线本身 | 三次、瞬时曲线随时间平移 | 近线性 x≈312+205·P，固定 | **完全不同**：Charter 渲染 ≠ 实机渲染 |
| 下落运动 | 平面匀速 ~1050px/s | 3D 隧道透视加速，x 恒定 | 渲染路径不同 |

### 8.5 对社区版渲染器的建议

1. **不需要复现轨道漂移**：正式游玩中 x(P) 固定，谱面确认视频的漂移是预览模式特有表现，与玩家实际看到的画面无关。
2. 渲染目标应以实机为准：center 映射近似 **`x = 312 + 205·P`**（1440×1080 坐标，P∈[0.2, 4.2] 验证，边缘 x 有 ±25px 矫正不确定度）；若要更准可用三次式 `−2.54P³+18.6P²+168.5P+326`。
3. 注意实机是 3D 隧道透视渲染（灭点收敛 + 下落加速 + x 恒定），平面复现时按"x 恒定、匀速"即可，观感差异主要来自相机而非谱面逻辑。
4. 谱面确认视频仍适合测**时间类参数**（OFF、判定线、速度量级、尺寸、Mixer/Type 外观），其几何结论与实机一致的部分已交叉验证；**凡涉及 x(P)/y(P) 映射的结论一律以实机视频为准**。
5. 侧轨 y(P) 时变问题（§7.1）在实机视频中未重新测量（侧轨在 3D 透视+手遮挡下数据太脏），仍列为开放问题，但鉴于 center 映射固定，侧轨映射大概率也是固定的，谱面确认视频里的"时变"同样可能是预览渲染差异。
