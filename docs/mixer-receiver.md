# Mixer 放置接收器（2026-10-14）

## 规则与证据

用户确认：短按放置、松手留头、头能接住身体即持续有效、八分音符漏接宽限；有效点击可同时操作 Mixer 与判普通 Note，无效候选位置忽略。
获批社区默认：宽限内节点直接 Perfect，宽限沿实际 `1/8 chart bar` 推进；多指为有效新按下接管、控制指滑动、失接时最近有效静止指接力。同距按 pointer id 稳定选择。
宽限到期等号失败，但同刻有效输入先应用。接收半宽采用谱面 width/2，皮肤内缩/光晕不参与，数值比较 epsilon=1e-10。
这不是本家全部边界的复刻声明。原逆向报告中“松手即断开、无宽限”的解释已撤回。

## 实现边界

- `shared/Judge/MixerRuntime.cs`：放置头、控制指、接收/宽限状态，重放输入及节点。
- `shared/Judge/MixerContactGeometry.cs`：候选位置与实际接收使用同一几何条件，枚举 legacy/v2 接收边界。
- `shared/Judge/MixerTimeline.cs`：v2 精确元数据运行时映射、legacy BPM 映射、无 BPM 时的烘焙路径回退。
- `V2PathEvaluator.AddReceiverBoundaries`：中心±半宽的多项式零点；在导数根处拆段后 52 次二分，支持 EaseInOut 分段、PCHIP 和 Hold 跳变。
- `client/scripts/game/gameplay/GameplayMain.Mixer.cs`：唯一屏幕逆映射、物理触点合法性过滤后的事件适配、提前成功头判授权、节点结果缓存、视图更新。
- `GameplayMain.JudgeHoldingPoint`：按原全局 sweep 顺序应用预计算结果，避免按 Mixer 分组结算改变 Combo。

输入与节点之间，收集已放置位置和所有活动触点的接收边界，逐个开区间推进；区间内接收归属不变，漏接起点取区间左边界而非发现它的渲染帧。
松手、暂停清理和窗口失焦只清控制触点，保留头；曲尾回收视图。实际接住才播放接收特效，宽限保分期间不假冒接触。

## 验证与实机清单

`tools/core-tests/Gameplay/MixerTests.cs` 直接调用生产状态机，覆盖短按/松手/无效点击、拖动与抢占、未知 Move、提前成功头判、自动演示、多指接力、帧内完整漏接恢复、30/60/144fps、变 BPM 宽限、六种曲线以及变宽 PCHIP 多项式分段。
旧测试中的 MixerCursor 镜像实现已删除，避免旧语义自我比较继续冒充当前行为验证。

实机待确认：

1. 中/侧轨短按放置后全部抬手，身体仍在范围时持续接收。
2. Tap+Mixer 同点输入，以及范围外 Tap 不挪动头。
3. 多指铺线、边缘换指、越界拖动，镜像与多个 Mixer 同时存在。
4. 宽限前后 Combo、重新接回，以及暂停/失焦后的原位头。
5. 低端设备密集曲线段性能和头边缘的视觉/手感。

构建与自动测试不代替这些实机验收；本次未运行 Godot 或导出 APK。

## 音频读数回退修复

用户报告 `Mixer time cannot run backwards`。旧状态机把实时音频读数当成严格递增；
SongClock 的播放位置/混音年龄/输出延迟独立读取可出现短暂回退，Stop/Play 恢复也会重新扣延迟。
日志未提供原始前后时间，无法区分当次具体来源。

修复：SongClock 同一播放周期共享 `MonotonicSongPosition`，回退时保持上次位置等待音频追上，
不人为累加时间；初始负延迟补偿保留，Resume 保留暂停下限，显式 Play/Seek 重置周期。
Mixer 防御性保留已提交游标，迟到输入在游标处按到达顺序执行，不丢松手，也不回滚已判节点或重置宽限。
适配层完成推进后才提交 tick 游标，显示使用实际已推进时间。
回归覆盖读数抖动、恢复延迟、迟到短按/松手、宽限不延期、节点不重复不漏计。
