# Twin Bloom — private Ramification gameplay workload

This developer tool takes the user-approved, locally stored osu!mania **Twin Bloom [Ramification]** (beatmap 5893787). It generates a standalone strict Dynamite UV 2.0 directory pack, not a public importer or an osu! gameplay simulation. It does not download anything. Keep the source `.osu`, local media and generated pack private and out of all release/export staging and recordings intended for sharing. The converter requires the beatmap and output under the repository’s ignored `.tmp/`. It does not copy the original `.osu`, background, video, hitsounds, or storyboard into the pack.

## Run from the repository root

Python 3.10+ is enough for audit-only. Playable conversion also requires `ffprobe` on `PATH` to check the user-provided untrimmed audio: MP3, 8/16-bit PCM WAV, Vorbis Ogg, or FLAC, mono or stereo. The audio is copied in full without transcoding or changing the start; `ffprobe` checks the container and duration, but cannot establish that the file is the correct, unshifted song. No audio is synthesized or substituted. No Godot is used by the tool or the strict validator.

```powershell
python -B tools/storyboard-demo/mania_local_chart.py `
  .tmp/osu-twin-bloom-research/current-official-5893787.osu `
  --audio .tmp/osu-twin-bloom-research/organizer-target/audio.mp3 `
  --start-ms 318204 --end-ms 338576

dotnet run --project tools/chart-tool -- validate-v2 .tmp/storyboard-demo/twin-bloom-ramification
```

Default pack root: `.tmp/storyboard-demo/twin-bloom-ramification`, chart ID `ramification`. Use `--output .tmp/storyboard-demo/<new-name>` for another run. The target must not exist, even if empty; an interrupted run may leave a partial directory. `--audit-only` needs neither `--audio` nor `--output` and writes no files. `--start-ms` and `--end-ms` are optional together; they do not affect the generated bytes. The pack contains the usual `meta.json`, `charts/ramification.json`, and full `audio.<ext>` only. The existing strict chart validator reports the expected duration-warning for MP3 because its media probe is WAV-only; the converter checks the MP3 separately.

## Mapping and limits

- `column = x * 4 // 512`, using integers `0 <= x < 512`. Four fixed sub-lanes on `notesCenter` use centers `0.625, 1.875, 3.125, 4.375` at width `1.0`; `notesLeft`/`notesRight` are empty. The four columns do not become four separate UV tracks.
- Every original Tap becomes a Tap. Every original Hold is a straight, fixed-width Hold with one explicit scored tail. Only the encoded head and end times are carried over. UV Hold scoring, input, note scroll, and visual presentation remain UV mechanics, not osu!mania release windows or score ticks.
- At the synthetic constant 150 BPM, one bar is exactly 1,600 ms. Each integer timestamp is emitted as the reduced fraction `ms / 1600` with zero audio offset. There is no beat-grid quantization; all heads, tails and simultaneous events retain exactly the same rational media time. Runtime audio clocks use ordinary floating point and follow existing offset and seek behavior. osu! timing points, SV, meter changes, and hitsounds are not mapped.
- The report checks same-column pairs on original media time. Same-ms heads are `duplicate-head`; an earlier Hold ending at a new head is `tail-touches-head`; a later Tap strictly inside an earlier Hold is `tap-inside-hold`; a later Hold strictly inside the earlier Hold's active span is `overlapping-holds`. For each pair the first matching category wins. This is an audit: conflicts are neither deleted nor displaced, so a chart with source conflicts may be awkward to play despite being structurally valid.

## Benchmark using the original media clock

A window is a half-open range `[start,end)` in raw media milliseconds. The tool audits the window, never trims the chart or audio, and reports Holds already active at seek or still pending at the exclusive end. Use the existing Editor/Internal verification settings and gameplay seek (environment only):

```powershell
$env:DUV_VERIFY_PACK = (Resolve-Path '.tmp/storyboard-demo/twin-bloom-ramification').Path
$env:DUV_VERIFY_MODE = 'v2'
$env:DUV_VERIFY_CHART_ID = 'ramification'
$env:DUV_VERIFY_AUTO = '1'
$env:DYNAMITE_UNIVERSE_START_SEC = '318.204'
```

Seek starts playback; it is not an end condition. The caller measures through the requested end on the media clock, then stops sampling or the run. The Prism Relay driver clears `DYNAMITE_UNIVERSE_START_SEC` and the original Prism sampler has a fixed window, so those unmodified defaults do not measure this excerpt. For steadier comparisons, seek a little earlier than the first sample to let the audio clock and existing judge cursor settle, and use the same settings and timing offset for all cases. A Hold straddling a seek still has its original earlier head; seeking does not emulate the manual input needed to hit it. Likewise, ending a sample inside a Hold does not resolve or shorten that Hold. For finger-play comparisons, select clean boundaries; do not shorten tails or insert replacement heads to make the cut work.
