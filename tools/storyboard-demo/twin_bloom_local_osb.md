# Twin Bloom: private official storyboard excerpts

This offline developer tool reads the locally supplied organizer `.osb` and its sibling textures. It copies the separately converted strict Ramification chart pack without modifying its metadata, chart or full audio, then adds the Editor/Internal storyboard binding. Nothing is downloaded. Do not commit, publish, export, upload to the shop, or publicly share the source media, generated packs, or recordings made from them. Both input and output paths must resolve below the repository’s ignored `.tmp/`. The generated packs have the same pack/chart identity as the chart-only baseline; select them by explicit path, not as simultaneous installs.

## Reproduce from the repository root

Python 3.10+ with Pillow is required; the validator uses the .NET SDK and production shared library. None of these commands starts Godot. The defaults read `.tmp/osu-twin-bloom-research/organizer-target/Gardens - Twin Bloom (elexire).osb` and `.tmp/storyboard-demo/twin-bloom-ramification`. The output directory must be new. If it already exists, pass a new ignored `--output` path.

```powershell
python -B tools/storyboard-demo/twin_bloom_local_osb.py --line-width 1600
python -B tools/storyboard-demo/twin_bloom_local_osb.py --start-ms 79000 --end-ms 87500 --output .tmp/storyboard-demo/twin-bloom-official-82-87p5
python -B -m unittest discover -s tools/storyboard-demo -p test_twin_bloom_local_osb.py

$primary = '.tmp/storyboard-demo/twin-bloom-official-192-204'
$secondary = '.tmp/storyboard-demo/twin-bloom-official-82-87p5'
dotnet run --project tools/chart-tool -- validate-v2 $primary
dotnet run --project tools/chart-tool -- validate-v2 $secondary
dotnet run -c Release --project tools/storyboard-demo/uvsb-local-check -- $primary 192000
dotnet run -c Release --project tools/storyboard-demo/uvsb-local-check -- $secondary 82000
```

For a different excerpt (at most 20 seconds), pass `--start-ms` and `--end-ms`. Use `--audit-only` to print the report without writing files. Conversion does not silently drop objects to fit resource limits; it rejects an over-budget result. The optional `--line-width` applies only to the six known section-9 line animation frames. No `--line-width` means native dimensions for every texture. `storyboard/index.json` binds `ramification` to `official-excerpt.uvsb`, and the sibling `conversion-report.json` records asset aliases/original and stored dimensions, alpha statistics, sprite windows, approximations, and budgets. The copied v2 chart remains full-length with 9,533 judgement units; the validator’s WAV-only probe emits the expected warning for the unchanged MP3.

## Measured input and limits

All times below are **raw media seconds**, half-open; seek a few seconds before measurement. The “peak” count is the shared sampler’s nonzero-opacity result at 1 ms increments, **before viewport culling**, not GPU draw calls, visible object count, or runtime performance.

| Profile | Script / seek | Measure | Objects in script / distinct measured / peak | Textures / pixels / compressed PNG bytes | KDL nodes / UTF-8 bytes |
| --- | --- | --- | ---: | ---: | ---: |
| Primary | `[189.000,204.000)`, seek 189.000 | `[192.000,204.000)` | 45 / 31 / 20 | 16 / 16,744,473 / 6,123,081 | 1,532 / 62,319 |
| Secondary (native) | `[79.000,87.500)`, seek 79.000 | `[82.000,87.500)` | 496 / 496 / 496 | 65 / 7,321,780 / 6,839,756 | 10,575 / 414,105 |

The primary at native size needs 20,546,073 pixels, over the **historical eager** 16,777,216-pixel limit. Omit `--line-width` to keep original sizes in the streaming runtime; use a distinct output directory to retain both profiles. Its six distinct 1920×1080 frames change every 200 ms and use alpha across their full bounds; shortening the scene to a few seconds still needs all six. A native `[192.000,192.700)` slice fits (14 textures and 16,398,873 pixels), but lacks a useful measurement duration and pre-roll. The primary profile explicitly resizes **only those six frames** to **1600×900**, with Lanczos and a **1.2× scale correction** per axis so the displayed quad size and pivot placement are unchanged. Their sampled alpha is resampled, not byte-identical. Other PNGs are preserved byte-for-byte, including the native 1721×1272 graph and 1280×720 glitch/glitch2/gradient layers. The gradient alone has 812,800 nonzero, non-opaque source pixels. Nothing is composited or flattened. Full `[82,95)` crosses a timed additive change not supported by a single UVSB sprite; extending the earlier native slice to `[79,90.650)` also exceeds the 12,000-node limit (15,710 nodes). The separate secondary profile ends earlier instead of dropping content or resizing.

Both recorded profiles passed strict chart validation and the shared compiler against generated PNG headers. Current offline limits are 1,024 declarations, 4096 px/axis, 16 MiB per PNG, 12,000 KDL nodes and 2 MiB strict UTF-8, plus bounded converter expansion and core timing/geometry work. `--preview-budget` on the converter and checker adds the historical eager preview constraints (128 declarations, 96 MiB RGBA8, 48 MiB compressed); it is not a runtime tier. Offline success is not playback or residency certification; see the [runtime budget](<../../docs/storyboard-residency-plan.md>).

## Translation and remaining approximations

- Sprite count is one-to-one for selected supported sources, including animated sprites. Draw order is stable by osu! layer then source line (both produced profiles select Background only). Position is centered on the 640×480 authored field with `(320,240)` mapping to `(960,540)` and a 2.25 stage-pixel scale. Origins map to UVSB pivots, positive angles are clockwise with radians converted to degrees, and source opacity multiplies the texture alpha. UVSB’s behind-the-HUD stage and black replacement backdrop are not a reproduction of the original player’s letterboxing or background/video/UI behavior. The replacement backdrop persists outside the excerpt while loaded.
- Loops expand on the original clock using the maximum local command end as their period. Expansion retains the neighboring iterations needed to establish values around the cut and does not restart a loop at seek. Numeric tracks take their first authored value before that property's first command, interpolate the effective command and hold the end through a gap. The converter resolves overlaps per component by latest start, then latest end, then source order. Display windows start at the first command and keep the source’s final integer-millisecond instant; UVSB closes the object at `last+1 ms` unless the excerpt ends sooner.
- UVSB native linear, Quad and Sine segments are emitted directly when retained intact; truncated nonlinear segments and unsupported selected cubic/exponential eases use adaptive linear keys. Fit targets are 0.33 stage px for translation, 0.35 stage px of scaled texture extent per axis, 0.15° rotation and 0.003 opacity, measured at seven subdivision probes per accepted span. These are fit targets, not an all-time error proof. Clipped nonlinear commands are evaluated at their original phase, with original endpoint values. When neighboring commands jump at the same millisecond, UVSB cannot put two keys there; a one-millisecond guard can hold the previous millisecond’s value before the jump. Static tint is carried as its original RGB bytes; animated tint is fit in UVSB’s linear-light space to the source’s sRGB-value interpolation, with byte quantization. No selected changing tint was needed for these profiles.
- Timed horizontal/vertical flip maps to step keys. A point `P` parameter lasts through the sprite’s end; a ranged parameter is treated as half-open. Constant normal/additive blending is preserved; varying blend and conditional Pass/Fail sprites are rejected, not omitted. Keep in mind UVSB and osu! do not guarantee identical tint, blend, or filtering at the pixel level.
- The primary `Animation` uses all six frames at the original 200-ms cadence. It is emitted as a bounded `once-hold` sequence with the correct partial first frame at the crop; `LoopForever` expansion and `LoopOnce` hold semantics work within the excerpt. Fractions, when encountered, round frame boundaries up to whole media milliseconds; neither produced profile uses fractional delays. Mixed-size animated frames are rejected. Input PNG files remain unchanged unless explicitly resized; JPEGs decode once to opaque RGB PNG, without further lossy encoding. Decoded RGBA-identical files at the same size share one texture ID; repeated references share one root texture, not atlas crops.
- The parser does not simulate hit-sound triggers, Samples, Video or original beatmap background events. This `.osb` declared no selected triggers and only one skipped non-sprite event (`vid.mp4` at 0 ms); its locally probed duration is 65.098367 s, so it intersects neither excerpt. Unknown command kinds or unsupported selected easing values raise an error.
