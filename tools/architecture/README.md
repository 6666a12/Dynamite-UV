# 结构检查

从 `community` 运行 `python -B tools/architecture/check.py`。完整非图形验证入口为
`python -B tools/verify.py`；依赖已还原时可加 `--no-restore`。

结构检查只用 Python 标准库，不启动 Godot，不安装依赖，不改源码。以下问题会返回非零退出码：

- [项目策略](<policy.json>)中的项目缺失，或 `ProjectReference`、显式 `Compile` 源码链接、`PackageReference` 与策略不符。游戏和制谱器各自引用公共展示程序集；编辑器不链接客户端源码，也不依赖 `.tmp` 研究源码。
- 受检源码目录缺失，或源码跨越显式约束的边界。例如公共渲染不能访问游玩场景/判定引擎/全局会话，浏览状态不能直接访问会话或播放器，纯核心不能导入引擎/UI 适配层。

可以加 `--report` 查看最大的源文件和选定类族的总行数（含注释、空行和内部类型）。这些数字仅供导航，**不设上限，不影响退出码**；类族汇总按文件中的声明匹配，不是编译器级的复杂度分析。

依赖规则是静态护栏，不代替编译、行为回归或设备验收。是否拆分看状态归属、输入输出、生命周期和依赖方向；拆完要有独立维护的理由和保留行为的证据，不以压缩行数或增加 `partial` 文件为目标。职责划分及历史入口见[模块地图](<../../docs/module-map.md>)。
